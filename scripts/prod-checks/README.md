**배포 URL을 실제 브라우저로 두드리는 검증 스위트.** 유닛테스트가 아니다.

이 프로젝트에서 발견된 주요 결함은 **거의 전부** 유닛테스트가 전부 통과하는 상태에서
이 스크립트들로만 드러났다. 반대로 이 스크립트들이 못 잡은 것은 유닛테스트도 못 잡았다.
버전관리 밖에 두면 PC를 바꾸는 순간 안전망이 통째로 사라지므로 여기에 둔다.

```bash
cd /c/업무/랄프톤
node scripts/prod-checks/sweep.mjs
```

## 읽는 법

**숫자만 보지 마라.** 판정 로직은 "행이 있고 에러가 없다"까지만 본다. 그것으로는
물어본 것과 다른 답을 걸러내지 못한다 — 신규 표현 10건 중 9건을 ✓로 세는 동안 실제로는
4건이 틀렸던 적이 있다. **실패 사례의 화면 글자를 직접 읽는다.**

판정 기준:
- 행이 0인데 안내가 정상이면 **실패**(사용자는 "데이터가 없구나"로 읽는다)
- 물어본 것보다 적게 답하면 **실패**(지표 셋을 물었는데 하나로 답하는 식)
- 방향이 반대면 **실패**
- 경고 없이 범위 밖·다른 단위로 답하면 **실패**
- 되물음은 실패가 아니다. 틀린 답보다 낫다.

## `public-api-access.mjs` 읽는 법

data.go.kr 서비스키·경로 문제를 세 가지로 가른다:

| 결과 | 뜻 | 조치 |
|---|---|---|
| `200 정상` | 경로 있음 + 이 키 승인됨 | 바로 호출 가능 |
| `403 미승인` | 경로는 있고 이 키가 그 오퍼레이션에 미승인 | 마이페이지에서 활용신청 |
| `400 경로없음` | 그 경로에 오픈API 자체가 없음(이름이 틀림) | 포털에서 Swagger의 "Base URL"을 다시 확인 — 추측하지 말 것 |

**대조군(`admmZZZZZZ`)이 `400 경로없음`이 아니면 오라클 자체가 무효다** — data.go.kr
쪽 사양이 바뀐 것이니 위 세 줄의 판정 로직부터 의심하라.

정상 요청만 던지면 "막혔다"까지만 보인다. 무엇에 막혔는지는 이 대조군과 비교해야
드러난다(2026-08-04, `docs/PUBLIC-DATA-ACCESS-2026-08-04.md`).

## 주의

- `values.mjs`가 46이 아니면 멈춰라. 가드를 잘못 넣어 46 → 42로 떨어진 적이 있고,
  그때 다른 검증은 전부 통과했다.
- **배포 직후 첫 실행은 콜드스타트(8초대)에 걸린다.** 안내가 "의도 파악 중…"으로 잡히면
  결함이 아니라 스크립트의 1.8초 대기가 짧은 것이다. 한 번 더 돌려서 갈라라 —
  두 번째부터는 1.2초대다.
- 로컬 서버(`next start`)가 떠 있는 상태에서 `npm run build`를 하지 마라. 실행 중인
  서버가 사라진 청크를 서빙해 CSS 없는 화면이 나온다.
- 일회성 재현 스크립트는 `.prod-*.mjs`(gitignore)로 남겨 둔다. 여기에는 **상시** 회귀만 둔다.
