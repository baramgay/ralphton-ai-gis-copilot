# 누리맵 — 시설을 **물었을 때도** 핀이 안 뜬다 (수정 지시 · 앞 판 대체)

작성 2026-09-06 · 대상 커밋 `f0b6326` (main) · 배포본 https://gnbc.site

> **이 문서의 앞 판은 「문구를 고쳐라」였습니다. 그것은 틀렸습니다.** 정책을 확인했습니다 —
> 핀을 아주 없애는 것이 아니라 **요청했을 때만 띄우는 것**이 맞습니다. 문구는 그대로 두고
> **코드를 고칩니다.** 아래를 정본으로 삼으세요.

## 0. 정책 (사용자 확인)

1. 화면의 중심은 **요청한 분석**이다. 단계구분도 + 호버 값이 기본이다.
2. 병의원 핀은 **기본으로 뜨지 않는다.** 생활인구·소비·재정 같은 분석을 보는 동안에도,
   의료기관 레이어를 고르기만 했을 때도 뜨지 않는다.
3. **시설을 직접 물었을 때만** 그 시설을 지도에 찍는다 — 「창원시 약국 위치」,
   「의령군 보건소 어디」, 「창원시 병원 위치 보여줘」 같은 질의.

`f0b6326` 은 3번까지 같이 꺼 버렸습니다. 2번은 맞게 껐습니다 — 되돌리지 마세요.

## 1. 증상 (배포본 실측)

| 질의 | 화면 글자 | 결과 목록 | 지도 |
|---|---|---|---|
| 창원시 약국 위치 | `약국 위치를 지도에 표시했습니다.` | — | **점 0개** |
| 의령군 보건소 어디 | `의령군 조건에 맞는 의료기관을 표시했습니다.` + `조건에 맞는 의료기관 22곳을 지도에 표시했습니다.` | 22곳 정상 | **점 0개** |
| 창원시 병원 위치 보여줘 | `창원시 조건에 맞는 의료기관을 표시했습니다.` | 1,361곳 정상 | **점 0개** |

「위치」를 물었는데 위치를 안 보여 줍니다. 목록은 나오지만 위치 질문의 답은 지도입니다.
화면 글자는 지금 **맞는 말**입니다 — 글자를 고치지 말고 지도가 그 말을 하게 만드세요.

## 2. 원인 (`f0b6326`)

`src/components/copilot/copilot-app.tsx` 지도 호출부에서 두 값이 상수로 박혔습니다.

```tsx
facilities={[]}          // ← 원래 mapFacilities
showFacilities={false}   // ← 원래 analysis.isFacilityResult
// onSelectFacility={selectFacility}  ← 지워짐
```

`analysis.isFacilityResult` 는 **시설을 직접 물었을 때만** 참입니다. 즉 이 조건은 위 정책
3번을 이미 정확히 표현하고 있었습니다. 상수로 덮는 대신 이 조건을 되살리면 됩니다.

## 3. 할 일

### 3-1. 시설 질의일 때만 핀을 되살린다 (필수)

- `showFacilities={analysis.isFacilityResult}` 로 되돌립니다.
- `facilities` 에 실제 목록을 넘깁니다.
- `onSelectFacility={selectFacility}` 를 되살립니다 — 핀을 눌러 그 시설이 선택되게.
  `selectFacility` 는 지금도 결과 목록에서 쓰이고 있어 그대로 씁니다.

**단, 기본 핀은 되살리지 마세요.** 1751~1757행의 `showMedicalFacilities = activeLayerId ===
"medical"` 갈래는 의료기관 레이어를 고르기만 해도 4,272곳을 얹습니다. 정책 2번 위반이니
이 갈래는 없애고, 핀 목록은 `analysis.isFacilityResult ? analysis.filteredFacilities : []`
하나로 정리하세요.

### 3-2. 표시 상한과 그 고지 (필수)

「창원시 병원 위치」는 1,361곳입니다. 상한 없이 다 찍으면 지도가 느려지고 서로 겹칩니다.

- 상한(`MAP_FACILITY_CAP`)을 다시 적용하세요.
- **잘랐으면 잘랐다고 화면에 적으세요.** 지웠던 고지를 되살립니다 —
  `지도 시설 900개 표시 · 전체 1,361`. 없으면 사용자는 지도의 점을 세고 전부라고 믿습니다.
- 4118행의 안내(`지도 시설 상한 900곳`)는 지금 아무 근거가 없는 문장입니다. 상한을 다시
  적용하면 참이 됩니다. 상한 값을 바꾸면 이 줄도 같이 맞추세요.

### 3-3. 손대지 말 것

- 호버 문구(세 단위 모두 실제 값) — 잘 돌아갑니다.
- 「지도에 표시했습니다」 계열 문구 6곳 — 이제 참이 됩니다.
- 지운 「지도 표시 옵션」(마커 범위·시설 유형 칩) — 되살릴 필요 없습니다. 시설 질의에서만
  뜨는 핀이라 유형 필터는 질의가 대신합니다.
- 첫 화면이 아무것도 안 칠하는 것, 상관 질의 수정 — 그대로.

### 3-4. 가드

시설 질의에서 핀이 뜨고, 분석 질의·레이어 선택에서는 안 뜨는 것을 유닛 또는 e2e로
고정하세요. 넣은 뒤 **일부러 `showFacilities` 를 false 로 박아 붉은불이 나는지** 확인하고
되돌리세요. 안 깨뜨려 본 테스트는 가드가 아닙니다.

## 5. 어기면 되돌리는 규칙

1. 최소 변경. 이 건에 직결된 줄만.
2. 색은 토큰으로(테마 전환이 색 유틸리티를 열거로 덮습니다).
3. 「읍면동」 금지 — 「행정동」. 주석 포함, 테스트가 잡습니다.
4. 화면 글자에 개발자 말투 금지(경로·상태 이름·변수명).
5. 로컬 초록만으로 완료라 하지 않습니다. 배포본으로 판정합니다.

## 7. 덧붙임 — 핀은 의료기관 전용이 아닙니다 (사용자 지시)

핀 자리를 **지점 자료 일반**으로 열어 두세요. 지금 코드는 지도의 점 경로가 `Facility`
(병의원·약국) 타입에 묶여 있고 색도 `FACILITY_TYPE_COLORS` 하나뿐입니다. 앞으로 다른 GIS
지점 자료(대피소·CCTV·어린이집·정류장 등)를 붙일 때 그 자료마다 지도 경로를 새로 뚫어야
하는 모양입니다.

**해야 할 것**

1. 지도에 넘기는 점 목록을 `{ id, name, lat, lng, kind, adm_cd2 }` 정도의 **자료 종류에
   중립적인 모양**으로 받게 하세요. 의료기관은 그중 한 종류가 됩니다.
2. 색·범례는 종류(`kind`)로 정하고, 목록에 없는 종류에는 기본색을 줍니다. 새 자료를 붙일 때
   지도 코드를 다시 손대지 않아야 합니다.
3. **켜는 조건은 그대로 「요청했을 때만」입니다.** 카탈로그의 `kind: "point"` 레이어를
   고르기만 한 것으로는 뜨지 않고, 그 지점을 묻는 질의(위치·어디·목록)일 때만 뜹니다.
   기본값은 어떤 자료에서도 **꺼짐**입니다.
4. 표시 상한과 「N개 표시 · 전체 M」 고지는 자료 종류와 무관하게 같은 규칙으로 겁니다.
5. 카카오 장소 검색 결과(`livePlaces`)는 이미 다른 점 경로로 그려지고 있습니다. 이번에
   합칠 필요는 없지만, 새 경로를 만들 때 **점 그리는 자리가 셋이 되지 않게** 하세요.

**하지 말 것** — 이 덧붙임을 이유로 지금 새 지점 자료를 붙이지 마세요. 이번 작업은 3절의
복구 + 위 1~4의 **구조만** 열어 두는 데까지입니다. 새 자료는 별도 건입니다.
