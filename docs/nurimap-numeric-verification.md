# 누리맵 수치 정확성 검증

검증일: 2026-10-05. 로컬 작업 환경은 Windows, Node.js/Vitest 및 Python 표준 라이브러리다. 아래 결과는 계산 라이브러리와 게시용 자료 파일에 대한 검증이며, 운영 화면·공유·다운로드의 통합 검증은 별도로 수행한다.

## 독립 산술 사례

아래 숫자는 회귀 검증을 위한 작은 예제이며 실제 지역 통계가 아니다. 기대값은 분석 구현을 호출하지 않고 분자·분모 또는 달력 간격으로 직접 계산했다.

| 사례 | 독립 기대값 | 수정 전 오류 | 수정 후 |
| --- | --- | --- | --- |
| 두 동의 인구 각각 100명, 면적 1·10km² | 200÷11 = 약 18.181818명/km² | 인구 가중 밀도 55명/km² | 총인구÷총면적 |
| 개인 매출 100·900, 청년 매출 50·90, 법인 매출 900·100 | 140÷1,000×100 = 14% | 전체 매출 가중평균 30% | 실제 청년 매출÷실제 개인 매출 |

양의 가중치에서 관측값이 없거나 비유한 수이면 시군구 가중평균은 `null`이다. 실제 가중치가 0인 구성원은 분자·분모에 기여하지 않는다. NH 집계에 필요한 실제 분자·분모가 없으면 다른 매출 계열이나 반올림된 비율로 추정하지 않는다. 행정동의 기존 유효값은 유지한다.

인구 큐브의 행정동 밀도도 저장된 반올림 밀도 대신 해당 인구÷해당 면적으로 계산한다. 합성 인구의 자료 성격은 그대로이며, 계산 수정이 인구 자료를 실측으로 바꾸지는 않는다.

## 실제 NH 원자료 재생성 검증

입력은 `C:\업무\민간데이터\NH 데이터`에 존재하는 2025년 1~12월 성연령별 및 시간대별 CSV 24개다. 원본 파일 합계 크기는 1,704,937,095바이트다. 원본은 변경하지 않았다.

- `nh-demographics.json`: 실제 개인·전체·청년·중장년·고령·여성·법인 매출을 반올림하지 않은 집계용 계열로 추가했다.
- `nh-hourly.json`: 실제 전체 시간대 매출과 반올림하지 않은 야간 매출을 집계용 계열로 추가했다. 주간·야간에 속하지 않는 시간대도 전체 매출 분모에 포함한다.
- 두 파일 모두 행정동 305개, 기준월 2025-12, 월 12개다.
- 재생성 전후 기존 공개 지표 32,940개를 전부 비교해 동일함을 확인했다. 기존 동별 금액·비중의 반올림과 결측값을 유지했다.
- 별도 Python CSV 판독과 `Decimal` 덧셈으로 원자료 22,373,472행을 다시 읽었다. 어댑터 코드를 호출하지 않고 실제 금액을 개인/법인·연령·성별·야간 구간으로 합산했다. 신규 분자·분모 및 원자료 미존재 시 `null`을 포함한 32,940개 값을 전부 검증했다. 허용 오차는 백만원 단위 `0.00000001`이다.
- 실제 원자료 없이 누락 분모를 복원하거나 새 값을 만들지 않았다. 별도 작업 파일 `scripts/adapters/nh-blocks.mjs`는 수정하지 않았다.

원자료 분자·분모 보존으로 JSON 크기는 성연령 큐브 188,680→664,988바이트, 시간대 큐브 115,638→237,530바이트로 증가했다. 자료는 기존처럼 해당 큐브 요청 시 읽는다. 화면 지연과 요청 크기의 영향은 통합 성능 측정에서 확인한다.

## 지역·단위와 기간 계약

상관·이상치는 요청한 지역을 계산 전에 제한한다. 대상 외 지역의 극단값이 대상 지역의 분류를 바꾸지 않는 회귀 사례로 검증했다. 명시한 시군구 단위와 화면 기본 단위를 실제 계산에 적용하며, 시군구에만 존재하는 지표는 시군구 단위로 계산한다. 설명도 요청에 따른 집계와 원자료 단위 제한을 구분한다.

시군구 이름은 창원시 의창구·성산구 등 실제 구를 보존한다. 코드로 별도 집계한 구의 이름을 창원시로 축약해 지역 필터에서 사라지는 문제를 수정했다.

`TrendResult`의 `firstMonth`, `lastMonth`, `elapsedMonths`는 유한 값이 존재하는 실제 첫·마지막 관측월 및 두 월 사이 간격이다. 날짜 없이 호출한 경우 월을 추정하지 않는다. `computeTrend(series, monthLabels)`는 실제 월 간격을 기울기의 분모에 사용한다. `TrendCrossRow.trendA/trendB`는 두 축의 관측 기간을 각각 보존한다. 순위·지역 프로파일은 같은 기간 계산을 사용한다.

UI 통합 시 단일 추세의 기준월은 `row.trend.lastMonth`, 추세 교차의 축별 기준월은 `row.trendA.lastMonth`·`row.trendB.lastMonth`를 사용한다. `describeTrend`에는 실제 시작·종료월과 관측 횟수가 포함된다. 큐브 기준월을 실제 관측 종료월로 대신 사용하지 않는다.

## 검증 명령

회귀 실패를 먼저 확인한 뒤 수정했다. 검증 명령은 다음과 같다.

```powershell
npm test -- tests/layers tests/adapters/nh-demographics.test.ts tests/adapters/nh-hourly.test.ts tests/analysis/nl-routing.test.ts
npm run typecheck
```

41개 파일의 796개 테스트, 타입 검사, 수정한 라이브러리·어댑터·테스트의 범위 ESLint와 `git diff --check`를 통과했다. 의료 접근이 어려운 지역을 묻는 질문이 시설 목록 대신 의료 취약 분석으로 연결되는 회귀를 포함한다.

독립 통합 검사 `node scripts/verify-nurimap-numerics.mjs`는 실제 큐브 21개와 운영 게시 인구를 읽어 336,002개 검사를 통과했다. 시군구 22개의 총인구÷총면적, 합계, NH 실제 분자÷분모, 유효 수치·결측·중복 코드·월 정렬을 확인하며 보고서는 `test-results/nurimap-numerics.json`에 남긴다. 분기 추세와 두 축의 마지막 관측월이 화면·CSV에서 보존되는 UI 회귀도 추가했다. 인구 합성값을 실제 인구의 정확성으로 표현하지 않는다.
