## 3. "근처"/"인근" — 큐브 지표에서 공간 제약 통째로 무시

**재현**
- "군부대 근처 상권" → 카드매출 상위 3곳 = 거창군 거창읍·진주시 천전동·김해시 진영읍
- "학교 근처 소비 많은 동" → **동일한** 카드매출 상위 3곳
- "터미널 근처 카드매출 높은 곳" → **동일한** 상위 3곳

무조건부 "카드매출 높은 지역"과 결과가 완전히 같다 — "근처" 조건이 통째로 사라졌는데 사용자에게 어떤 신호도 없다.

**원인 추정**: 카드매출 등 큐브 지표는 행정동 단위로 사전집계돼 있어 임의 지점(군부대·학교·터미널)과의 거리 조인 기능 자체가 없다. 반경검색은 의료기관 포인트 레이어에만 구현돼 있음. 구조적 한계이므로, 고칠 거면 "이 지표는 근처 필터를 지원하지 않습니다" 같은 caveat을 붙이는 쪽이 현실적.

## 4. 비의료 시설 요청 → 조용히 의료기관으로 치환

**재현**: "1km 안에 편의점 많은 동" → 안내 "대표점 기준 1km 반경 **의료기관** 수를 비교했습니다"

**원인**: `src/lib/analysis/query-signals.ts:182-191` `extractFacilityTypes()`의 시설 사전이 의료기관 8종뿐(종합병원·요양병원·치과의원·한의원·보건소·약국·의원·병원). "편의점"은 목록에 없어 `facilityTypes`가 빈 배열이 되고, 반경검색 도구가 매칭 실패 시 기본값으로 "의료기관 전체"를 센다. 시스템에 비의료 POI 데이터 자체가 없다(카드매출 소비비중(%)으로만 간접 존재).

## 5. 3개 이상 지역 비교 → 2개로 조용히 절단

**재현**: "창원 김해 진주 중 어디가 나은가" → 안내 "창원시 · 김해시 구·군 단위 지표를 합산 비교합니다" — **진주 누락**, 잘렸다는 언급 없음.

**원인**: `src/lib/analysis/query-catalog.ts:378`
```js
s.districts.length >= 2 ? s.districts.slice(0, 2) : ...
```
하드코딩된 2개 상한.

*참고*: 지표 없이 "창원이랑 김해 중 어디가 나은가"만 물었을 때 나오는 "구·군 단위 지표를 합산 비교합니다"라는 범용 문구 자체는 **의도된 설계**(무지표 질의 처리 방식)로 확인됨 — 이건 결함 아님.

## 6. FALLING_CUES 누락 — "준"류 관형사형 축약

**재현**
- "소비가 줄고 있는데 인구는 늘고 있는 동네" (round5, 기존) → ✓ 정상 교차 ("카드매출 감소 × 총인구 증가")
- "작년보다 소비 늘고 인구 준 동" (신규) → ✗ "카드매출 증가"만 답함, 인구 조건 소실

**원인**: `src/lib/layers/resolve-trend-cross-query.ts:36`
```js
const FALLING_CUES = ["감소", "줄어", "줄고", "주는", "줄", "하락", "떨어지", "축소", "작아지", "적어지"];
```
"줄다"의 관형사형 축약 "준"(예: "인구가 준 동")이 목록에 없다. `directionAfter()`가 두 번째 지표의 방향을 못 읽어 `null` 반환 → `resolveTrendCrossQuery`가 통째로 `null`(line 110) → 단일지표 폴백.

## 7. "의료" 일반어 — 교차분석 트리거에 없음

**재현**: "의료도 부족하고 소비도 적은 곳 5곳만" → 안내 "카드소비 · 카드매출 레이어로 전환" (의료 조건 무시), 결론도 "가장 낮은 3곳"으로 고정 출력(요청한 5와 불일치)

**원인**: `resolve-cross-query.ts`의 `allMatches`는 2개의 **큐브 지표** 매칭을 요구한다. "의료"는 `medical_store_share` 지표 트리거(`"의료 업태"`, `"약국 ~"` 리터럴)에도, 시설검색 키워드(`"병원"/"약국"/"치과"/"한의원"`)에도 안 걸린다. "의료"라는 흔한 표현이 두 사전 사이 빈틈에 있어 매칭 0건 → distinct 지표가 1개("소비")뿐이라 교차 조건(`ordered.length < 2`)에서 탈락 → 단일지표 폴백.

## 8. "1인가구" ≠ "가구" — 전용 지표 없음

**재현**: "1인가구 많고 소득 낮은 동" → 안내 "세대수(공공) 대비 평균소득(KCB)" 교차로 답함

**원인**: `catalog.ts:13`
```js
{ key: "households", label: "세대수", ..., triggers: ["세대", "가구"] }
```
"1인가구"라는 문자열 안에 "가구"가 포함돼 그냥 걸린다. 전용 "1인가구 비중" 지표가 아예 없어, 세대수(총 가구 수, 절대량)로 조용히 대체 — 실제로는 완전히 다른 개념인데 캐비엇 없이 답한다.
