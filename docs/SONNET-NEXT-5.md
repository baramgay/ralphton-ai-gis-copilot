### ① `verify-d` 완주 실패는 인프라 문제가 아니었다

원인은 스크립트 자신이었다.

```js
page.getByTestId("query-caveat").textContent().catch(() => "")
```

요소가 없어도 즉시 실패하지 않는다. **Playwright 기본 대기 30초를 다 채운 뒤** 거절한다.
고지·모수처럼 *있을 때만 있는* 요소를 이렇게 읽는 자리가 **17개 스크립트에 44군데**
있었다. verify-d는 그런 질의가 많아 완주에 20분이 넘었다. `{ timeout: 1500 }`을 주니
17/17 완주(`316bbe1`).

5회를 시도하면서 **스크립트 코드를 한 번도 안 읽었다.** "다른 스크립트에서는 같은 질의가
정상"이라는 관찰까지 해 놓고 프로세스를 뒤졌다 — 그 관찰이 가리키던 곳은 *질의*가 아니라
*그 스크립트가 읽는 선택적 요소의 유무*였다.

> **"가끔 없는 것"을 기다리는 코드는 없을 때가 정상 경로다.** 그 경로에 기본 타임아웃이
> 걸려 있으면 정상 동작이 장애처럼 보인다.

### ② 프로파일 패널이 시군구에서 안 뜨는 이유

추측: "시군구 합산값에 대응하는 뷰가 없어서". 실제:

```ts
const region = snapshot.regions.find((item) => item.adm_cd2 === selectedRegionCode);
if (!region) return null;
```

롤업 코드 `4817000000`은 스냅샷 읍면동 목록에 없다 — **단순 조회 실패**다. 파일 하나를
열면 끝날 일이었다. 추측이라고 표시한 것은 옳았지만, **확인할 수 있는 추측은 확인하라.**

### ③ 고령비율 방향 — 발견은 옳고, 지금은 고치지 않는다

실재하는 결함이고 "줄어/감소"로 재현해 원래 있던 것임을 보인 것도 정확했다. 다만 데이터를
열어 보니 고령비율 12개월 변화의 **전체 범위가 −0.035 ~ +0.055%p**였다. 지금 방향을
만들면 노이즈의 반대쪽 끝을 줄 세울 뿐이다. 실인구가 들어온 뒤에 판단한다.

### ④ 그 조사에서 나온 더 큰 것 — 이번 차수의 배경

`mode: "live"`인데 인구·세대는 합성값이었고, 화면 배지는 "실데이터"라고 적혀 있었다.

## 배경 — 왜 이 일을 하나

인구 live 피드는 **한 번도 동작한 적이 없었다.** 요청이 API 규격과 달라 어떤 달을 물어도
0행이었고, 그 사실이 "월 공개 지연"으로 설명돼 3개월 폴백까지 만들어져 있었다 —
**대책이 있다는 사실이 진단이 맞다는 증거처럼 보였다.**

`229f531`에서 인구·세대는 고쳤다. 그런데 같은 파일에 **같은 방식으로 만들어진 데이터셋이
4개 더 있다**:

```ts
// src/lib/data/public-api.ts
ageSexPopulation:    '/1741000/admmSexdAgePpltn/selectAdmmSexdAgePpltn'   // 고령·청년·생산연령
onePersonHouseholds: '/1741000/admmSexdAgeOneHh/selectAdmmSexdAgeOneHh'   // 1인가구
births:              '/1741000/admmBrthRegist/selectAdmmBrthRegist'       // 출생
deaths:              '/1741000/admmDthRegist/selectAdmmDthRegist'         // 사망
```

**이 넷은 한 번도 호출된 적이 없다.** 지금 화면의 고령비율·1인가구·출생·사망은 전부
합성값이고, 그 위에서 도는 도구가 여럿이다(고령화 속도, 1인가구 위험, 자연증가 등).

## 이번 차수의 과제

### ① 4개 데이터셋의 규격을 실측한다 (핵심)

인구와 같은 `1741000`(행정안전부) 계열이라 **같은 규격일 가능성이 높다**. 그러나
**추측하지 말고 두드려라.** 인구에서 확인된 규격이 출발 가설이다:

| 항목 | 인구에서 확인된 값 |
|---|---|
| 필수 파라미터 | `serviceKey`, `admmCd`(읍면동 10자리), `srchFrYm`, `srchToYm` |
| 기간 한도 | 4개월 (5개월부터 `QUERY_PERIOD_LIMIT_EXCEEDED`) |
| 응답 경로 | `Response.items.item[]` · 헤더는 `Response.head` |
| 행 단위 | 통·반 (겹치지 않음 → 단순 합산) |
| 공개 지연 | 없음 (기준월 202606 조회됨) |

**방법 — 오류 코드 사다리.** 인구에서 이렇게 규격을 역추적했다. 그대로 쓰면 된다.

```
11 NO_MANDATORY_REQUEST_PARAMETERS  → 필수 파라미터가 빠졌다
10 INVALID_REQUEST_PARAMETER        → 이름은 맞는데 값이 틀렸다  ← 필수 항목을 찾은 신호
13 QUERY_PERIOD_LIMIT_EXCEEDED      → 파라미터는 통과, 기간만 길다 ← 형식이 맞다는 신호
 3 NODATA_ERROR                     → 요청은 유효, 그 조건에 데이터가 없다
 0 NORMAL_SERVICE                   → 성공
```

오류 코드가 **바뀌는 지점**이 정보다. 하나씩 더하고 빼면서 코드가 어떻게 움직이는지 보라.

각 데이터셋마다 확인할 것:
1. 필수 파라미터가 인구와 같은가 (다르면 무엇인가)
2. 기간 한도가 4개월인가
3. 응답 경로가 `Response.items.item`인가
4. **행이 어떤 단위인가** — 통·반인가, 연령대별인가, 성별×연령대인가
5. **필드명이 무엇인가** — 인구는 `totNmprCnt`였다. 코드의 후보 목록과 맞는지 확인하라
6. **합산 규칙** — 겹치는 행(소계·합계)이 있는가. 있으면 단순 합산이 틀린다
7. 최신 가용월이 언제인가

**⑤와 ⑥이 가장 중요하다.** 인구에서도 필드명(`totNmprCnt`)이 후보에 없어서, 응답이
정상인데 0행으로 읽고 있었다. 그리고 연령·성별 데이터셋은 **합계 행이 섞여 있을
가능성이 높다** — 그러면 단순 합산이 인구를 두 배로 만든다. 실제 행을 눈으로 확인하라.

**호출 예산을 아껴라.** 읍면동 1~2곳으로 규격을 확정하고, 305곳 전체는 절대 돌리지 마라.
규격 확인에 필요한 호출은 데이터셋당 10~20회면 충분하다.

키는 `.env.local`의 `DATA_GO_KR_SERVICE_KEY`다. **값을 출력하지 마라.**

### ② 확정된 규격을 문서로 남긴다

`docs/PUBLIC-DATA-API-SPEC.md`를 새로 만들어 5개 데이터셋(인구 포함)의 규격을 한 표로
정리하라. 인구는 이미 확인됐으니 그대로 옮기고, 나머지 4개를 채워라.

각 항목마다 **"실측"인지 "추정"인지 표시하라.** 안 두드려 본 것을 두드려 본 것처럼
적으면 다음 사람이 그 위에 코드를 쌓는다 — 이번 인구 결함이 정확히 그렇게 생겼다.

### ③ 구현은 하지 마라 (이번 차수)

어댑터 구현은 규격이 다 나온 뒤 한 묶음으로 한다. 이번에는 **규격 실측과 문서화까지**다.
다만 명백한 오류(필드명 누락처럼 한 줄로 끝나는 것)를 발견하면 적어만 두고 넘어가라.

### ④ 남는 시간에 — 4차가 못 본 것 둘

- **격자 값조건의 부분 필터 경계값**: 0건과 무필터(24행) 양극단만 확인됐다. 그 사이로
  걸러지는 임계값을 이분 탐색으로 찾아 `combo.mjs`에 판정으로 넣어라.
- **슬라이드·HWP를 비율·값조건 조합까지**: 지금은 시군구 조건에서만 4개 표면을 전부 봤고
  나머지 조건은 CSV 위주로만 봤다.

## 규칙

1. **배포 URL로 검증한다.** 유닛테스트 통과는 증거가 아니다.
2. **추측을 추측이라고 적어라.** 4차에서 프로파일 패널이 안 뜨는 이유를 "대응 뷰가 없어서"로
   추측했는데 실제로는 코드 조회 실패였다. 추측 자체는 문제가 아니고, 표시를 안 하는 것이
   문제다.
3. **"없다"는 진단은 코드·응답으로 확인한 뒤에만.**
4. **모수를 세라.** 데이터셋이 4개면 4개 다 확인한다. 하나만 보고 "같은 계열이니 같겠지"는
   이번 인구 결함을 만든 사고방식이다.
5. 고칠 때는 **결함 주입**으로 테스트가 실패하는지 먼저 확인하라.

## 절대 하지 말 것

- **`/api/data/sync`를 실행하지 마라.** 성공하면 prod 데이터가 통째로 바뀐다. 대외 반영이라
  사용자 판단 사항이다. `DATA_SYNC_SECRET`도 출력 금지.
- `.env.local`의 어떤 키 값도 출력하지 마라.
- 305개 읍면동 전체 호출 금지(규격 확인에 불필요하고 할당량을 태운다).
- METIS·팔란티어 언급 금지 → "온톨로지 방식의 통합 데이터 플랫폼"
- `next start`가 떠 있는 상태에서 `npm run build` 금지.
- 민간 큐브 데이터 외부 유출 금지(도 담당자 인가 사항).
