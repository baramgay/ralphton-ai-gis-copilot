## 3. 내가 찾은 결함 — 시안에서 고쳤다

스크린샷을 눈으로 보면 둘 다 「대체로 괜찮다」로 지나간다. 상자와 히트 테스트로 물으니
나왔다(`scripts/verify-design-mockups.mjs`).

### 3-1. 지점 카드 머리글이 선택 칩에 가린다 (01·02·05, 11건)

`.query-hero`는 `z-index:50`이고 `.probe-card`는 `12`다. 히어로 안의 칩 줄이 두 줄로
늘어나면서 카드의 **이름·좌표·닫기(✕)** 위를 덮었다. 05에서는 접기(▾)와 닫기(✕)가
**눌리지 않는다** — 카드를 닫을 수 없다.

겹침 넓이로 재면 안 된다. 겹쳐도 위가 투명하면 눌리고, 겹치지 않아도 그림자 층이 가린다.
`elementFromPoint`로 **카드 안 글자가 자기 자신에게 히트되는지**를 물어야 나온다.

고침: 카드가 열리면 선택 칩이 물러선다. 클래스 이름이 이미 `is-optional`이라고 말하고
있었다 — 자리를 다투면 물러설 쪽은 정해져 있었다.

```css
.copilot-map:has(.probe-card:not([data-collapsed="yes"])) .query-hero-chips.is-optional { display: none; }
```

z-index를 올려 카드를 위로 보내는 쪽은 택하지 않았다. 그러면 칩이 조용히 안 눌리는 상태가
된다 — 보이는데 안 눌리는 것이 안 보이는 것보다 나쁘다.

### 3-2. 고대비에서 부유 버튼이 두 줄로 접힌다 (05, 3건)

「조작」·「결과」·「지점 분석」이 전부 두 줄. 고대비의 굵기 800과 넓은 자간이 글자를 밀고,
`.map-float-btn`에 `min-width:44px`만 있어 flex가 내용 폭 아래로 줄여 버렸다.
의뢰서 부록 C에 적어 둔 함정 2번이 그대로 재발했다.

고침: `flex: 0 0 auto; white-space: nowrap;` (6개 시안 전부).

⚠️ **접힘은 상자 높이로 재면 안 된다.** flex로 세로 가운데 맞춘 버튼은 한 줄이어도
상자가 높다 — 높이 기준으로 세면 「1km」·「↑」까지 걸려 거짓 양성 32건이 나왔다.
`Range`로 텍스트 노드의 줄 상자 수를 세야 한다.

### 검사가 실제로 잡는지 확인

고친 뒤 초록이 된 것만으로는 「검사가 못 보는 것」과 구분되지 않는다. 05에 두 결함을 다시
심었더니 **8건으로 붉게** 갔고, 되돌리니 초록으로 돌아왔다.

## 4. 과장 1건 — 수치로 바로잡음

MATERIALS.md가 「두 극단 모두 최악 쌍이 **7.8:1 이상**」이라고 적었으나, 같은 폴더의
MEASURED.md 표 1이 말하는 실제 최솟값은 **4.76**이다. 통과는 통과지만 여유가 실제보다
크게 적혔다. 4.76으로 고쳤다.

**단조성 논증도 좁혔다.** 「합성은 타일 색의 단조 함수라 극단 둘만 재면 된다」는 절반만
맞다. 합성 바탕의 *휘도*는 단조지만 **대비비는 단조가 아니다** — 글자 휘도가 두 극단
사이에 있으면 그 중간에서 최소가 된다(V자). 이번에 쓰인 글자는 전부 합성 바탕 범위 밖이라
결론은 살지만, 논증을 그대로 두면 다음에 **중간 휘도 글자**를 얹을 때 잘못된 통과를
내준다. 타일을 0~255 전 구간 훑어 최솟값이 실제로 끝점에 있음을 확인하고, 문서에 조건을
달았다.

부수적으로 Kimi의 「순흑 타일」은 `#000`이 아니라 `rgb(10,10,12)`였다. 진짜 검정으로
다시 재면 라이트 유리 72% `--text-1` 9.21 → **9.00**, `--text-2` 5.34 → **5.22**로 내려간다.
전부 AA 유지이고 하한 4.76은 다크 쪽이 정하므로 결론은 그대로다.

## 5. 스스로 못 봤다고 적은 것 (그대로 인정)

MEASURED.md §6이 넷을 적었다. **이 태도가 이 답변에서 가장 쓸모 있는 부분이다.**

1. 실기기 Pixel 5 실측 — 없음. 헤드리스 소프트웨어 래스터는 worst case 경로다.
2. 실제 카카오 타일 위 스포이드 측정 — 없음. 극단 합성 근사로 대체(위 §4에서 조건을 달았다).
3. **FCP 195ms / h1 205ms 예산 영향 — 안 쟀다.** 이식 후 반드시 다시 재야 한다.
4. Safari/Firefox의 `backdrop-filter` 비용 — Chromium 141 한 점만 봤다.

3번이 이식 단계의 숙제다. 「CSS만 바꾸니 영향 없을 것」은 판단이지 측정이 아니다.

## 6. 이식할 때 지킬 것

- `--glass-*`는 **지도 위 부유층 전용**. 패널·순위표에 쓰면 숫자 읽기가 나빠진다.
- 새 토큰은 `:root`(라이트)에 **먼저** 기본값을 둔다. 어두운 블록에만 정의하면 라이트에서
  조용히 사라진다(이미 겪은 함정).
- 유리 위 글자는 `--text-1`/`--text-2` + 굵기 600 이상. **색 글자 금지** — 색은 도형이 나른다.
- Tailwind v4에서 가운데 정렬을 덮을 때는 `transform`이 아니라 `translate`.
- 이식 후 회귀: 유닛 1,730 · e2e 18 · `verify-terms-prod` 12 · **FCP/h1 재측정**.
