## 과제 1. 돈은 어디서 오나 — 유입지별 카드매출 (최우선)

### 왜 지금인가
사람 흐름과 **똑같은 모양의 발견**이 카드 자료에 그대로 남아 있다.
`경상남도_1_유입지별카드매출_YYYYMM.csv`는 파일 이름부터 「유입지별」인데,
현재 어댑터 4개(`nh-consumption` / `nh-industry` / `nh-storetype` / `nh-demographics`)가
**유입지 두 컬럼(5 이용자_시도, 6 이용자_시군구)을 한 번도 읽지 않는다.** 전부 동별로 합쳐 버린다.

확인법: `grep -n "COL\s*=" scripts/adapters/nh-*.mjs` — 인덱스 5·6이 어디에도 없다.

### 이미 재 본 값 (2025-12, 전체 파일 스캔)
- 경남 전체 카드매출 **2조 2,309억원**
- 그중 **관내(같은 시군구 거주자) 80.6% = 1조 7,984억원**
- 즉 **관외 소비는 19.4%(약 4,325억원)** — 이게 「외지 손님이 쓰고 간 돈」이다
- 유입지 시도 상위: 경남 343,495행 · 부산 20,352 · 울산 5,277 · 전남 3,296 · 경북 2,543 · 대구 2,535

### 만들 것
1. `scripts/adapters/nh-flow.mjs` — 동(또는 시군구)별로 **관외 유입지 상위 N곳의 카드매출**을 집계.
   출력은 `public/data/flows/nh-flow.json`, 모양은 `skt-flow.json`을 따라가면 화면 쪽 재사용이 쉽다.
2. 새 지표 후보 (`src/lib/layers/catalog.ts`)
   - `outside_sales_share` — 관외 매출 비중(%). **정책적으로 이게 핵심이다**: 관광·상권 유입 의존도.
   - 시군구별 「돈이 오는 곳 상위 5」 목록 — 사람 흐름 패널 옆에 나란히.
3. 화면: 기존 `region-flow` 패널에 붙이는 편이 낫다. 「사람 99,433명이 오고, 돈은 부산에서 온다」가
   한 화면에서 읽혀야 의미가 산다.
4. 배포본 검사 `scripts/verify-nh-flow.mjs` — `verify-prod.mjs`에 등록.

### 함정 (반드시)
- **관내를 빼라.** 안 빼면 80.6%가 자기 자신이고, 순위는 흐름이 아니라 그 도시의 소비 규모를 잰다.
- **NH는 코드가 아니라 이름으로 준다** (`경남`,`김해시`). SKT는 코드로 준다. 두 자료를 나란히 놓으려면
  이름↔코드를 맞춰야 한다. 매핑표 `C:\업무\민간데이터\(매핑테이블)행정동코드_5자리(시군구 단위)_260624.csv`의
  이름과 NH 이름은 **그대로 일치**한다(`창원시 의창구` 띄어쓰기까지). 확인함.
- **「중구」는 여섯 곳이다.** 경남 밖 상대에는 시도를 붙여라(`skt-flow.mjs`의 `SIDO_BY_PREFIX` 재사용).
- 금액 컬럼은 **10번(전체카드이용금액, 전수화)** 이다. 8번(농협금액)은 농협 몫만이라 값이 작다.
  기존 어댑터가 10번을 쓰므로 맞춰라.
- 파일에 **헤더가 없다.** 고정 인덱스 접근이고, BOM이 붙어 온다(`nh-consumption.mjs`의 `cleanDongCode` 참조).

## 과제 2. 블록별 카드매출을 지도에 올린다 — 「매핑이 없다」는 오진이었다

이전 세션에서 「NH 블록 ID를 좌표로 바꿀 매핑을 못 찾았다」고 적었다. **틀렸다. 직접 재 봤다.**

- NH 블록 파일: `경상남도_4_블록별유입지별카드매출_YYYYMM.csv` (60MB, 헤더 없음)
  컬럼 0=블록ID(한글, 예 `라마887292`), 1=블록ID(로마자, 예 `DE887292`), 2=기준일자, …
- 좌표표: `C:\업무\민간데이터\격자변환\grid_100m_centroids_wgs84.csv` (106만 행, `gid,center_x_5179,center_y_5179,longitude,latitude`)
- **2025-12 블록 7,328개 중 7,244개(98.9%)가 그대로 매칭된다.** 미매칭 84개는 경남 밖으로 보인다(확인 필요).

즉 동보다 훨씬 촘촘한 상권 지도를 그릴 재료가 이미 손에 있다. 파일 3·5·6도 같은 블록 ID를 쓴다.

### 열어 보고 결정할 것
- 블록의 **실제 크기**. ID 공간은 국토통계격자 100m인데 자료 설명은 250m 블록이다.
  실측한 최소 간격이 200m라 둘 중 무엇인지 아직 못 정했다. 명세서
  `C:\업무\민간데이터\(데이터명세서)NH_카드소비데이터_260624.xlsx`를 먼저 읽어 확정하라. **추측 금지.**
- 비식별 하한. 블록 단위 매출은 점포 한 곳이 드러날 수 있다. 표시 하한(건수·점포수)을 정하고,
  하한 미달은 **0이 아니라 「자료 없음」으로** 남겨라.

## 과제 3. 흐름이 화면 밖으로 못 나간다

사람 흐름은 지금 **화면 목록에서만 산다.** 확인함 — `region-flow`를 참조하는 파일은
화면·검사·시험뿐이고, 내보내기 쪽(`export-csv.ts` / `export-report.ts` / `export-a4.ts` /
`export-hwp.ts` / `export-slide.ts`)에는 한 줄도 없다.

- 보고서로 인쇄하면 **사람 흐름이 사라진다.** 담당자가 회의에 들고 가는 건 인쇄물이다.
- 12개월 자료가 있는데 **기준월 한 달만 보여 준다.** 계절성(관광·휴가철 유입)이 통째로 안 보인다.
- 비교 질의(「김해랑 양산 중 어디가 외지 유입이 많나」)는 흐름으로 안 간다 — `query-rules.ts`에서
  `compare`가 있으면 흐름 분기를 건너뛴다(의도된 것, 다만 미구현).

## 이 레포에서 지켜야 할 것

**검증**
- 게이트: `npm run verify` (시험 → 타입 → lint → 빌드). 현재 142파일 1,886건 통과.
- 배포본: `npm run verify:prod` — 14개 스크립트를 **종료 코드로** 판정한다.
- **게이트를 파이프 뒤에 두지 마라.** `gate | tail && deploy`는 붉은 게이트로도 배포한다.
  로그로 빼고 `echo exit=$?`로 읽어라.
- **새 검사는 일부러 깨뜨려 붉은불을 본 뒤에 믿어라.** 초록불은 「위반 없음」과 「검사가 못 봄」을 구분 못 한다.
- 배포 전 `git fetch` 후 `git rev-list --left-right --count origin/main...HEAD`가 `0 0`인지 확인.
- 배포 후 `curl -s https://gnbc.site/api/health`의 `build.commitSha`가 HEAD와 같은지 확인하고 나서 검사.

**자료 다룰 때**
- 결손을 좋은 값으로 메우지 마라. `?? 0`·`catch(()=>null)`이 안전한 쪽이면 자료 결손이 정상으로 인쇄된다.
- 합계에 자기 자신이 들어 있는지 먼저 재라(과제 1·2 모두 해당).
- 방향이 있는 자료는 **양쪽 파일을 맞대라.** 「A로 들어오는 B」와 「B에서 나가는 A」가 같아야 한다.

**표기**
- 「읍면동」 쓰지 말고 **「행정동」**.
- 제공기관 이름(SKT·NH농협카드·KCB·KOSIS 등)은 **지우지 마라.** 여기에 **제공 창구 「경남빅데이터허브플랫폼」**을
  덧붙인다(`src/lib/layers/channel.ts`의 `withHubChannel`). 창구가 기관을 대신하지 않는다.
- 화면에 나가는 글에 개발자 어휘 금지 — 파일 경로·실행 명령·`null`·라이브러리 이름.
- 색은 테마 토큰으로. 새 색 유틸리티·그라디언트 금지(테마 전환이 색을 하나씩 열거해 덮기 때문에
  열거에 없는 클래스는 바탕에 묻힌다 — 빌드·lint·타입 전부 초록인 채로).
- 커밋 메시지는 한글 한 줄, 무엇을 왜 바꿨는지.
