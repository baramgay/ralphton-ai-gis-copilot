## 0. 당신에게 부탁하는 일

경상남도 공간데이터를 자연어로 묻고 지도·순위·보고서로 답하는 웹앱이다. 최근 한 라운드에서
데이터(14→22레이어, 52→79지표), 분석(상관·이상치), 검색(RAG), 지도(지점 반경 분석)를 한꺼번에
올렸다. **구현은 끝났고 자체 검사는 전부 초록이다.** 그래서 부탁하는 것은 "돌아가는지"가 아니라
**"답이 참인지"**다.

이 앱의 주된 결함 유형은 "답을 못 하는 것"이 아니라 **"다른 답을 자신 있게 하는 것"**이다.
공공기관이 정책 판단에 쓰는 화면이라, 그럴듯한 숫자 하나가 "자료로는 말할 수 없다"보다 나쁘다.

### 판정 규칙

1. **"괜찮아 보인다"는 답으로 치지 않는다.** 각 항목마다 `참 / 거짓 / 판단 불가` 중 하나를 고르고,
   그 근거를 `파일:줄` 또는 실행 결과로 댄다.
2. **거짓이면 재현 절차를 적는다.** 어떤 입력에서 어떤 잘못된 출력이 나오는지. 고치는 방법은
   그다음이다.
3. **초록불을 신뢰하지 마라.** 이 저장소의 검사는 1,697개가 통과한다. 이번 라운드에서 자체적으로
   잡아낸 결함 셋은 모두 **검사가 통과하는 상태**에서 나왔다:
   - 자릿수 검사가 기대값에 상수를 그대로 써서 자기 자신을 재고 있었다(상수를 12로 바꿔도 초록)
   - 검색 품질 문턱만으로는 우선순위 장치를 **없애도** 초록이었다
   - 창원 접기는 검사가 통과했는데 배포본에서는 헛돌았다(고정물에 「창원시 의창구」라고 공백을
     넣어 뒀는데 실제 이름은 「창원시의창구」)
   → 검사를 읽을 때는 **그 검사를 통과시키는 가장 게으른 구현**을 상상하고, 그것도 통과하는지 보라.
4. **모르는 것은 모른다고 하라.** 자료를 못 봐서 판단이 안 서면 `판단 불가`와 함께 무엇이 있어야
   판정할 수 있는지 적는다.

## 1. [최우선] 상관계수의 표본 수가 부풀려져 있는가

**의심의 요지: n=22라고 적고 있지만, 그중 5개는 서로 완전히 같은 값이다.**

### 사실관계

- KOSIS e-지방지표는 **창원시를 한 행**으로 준다. 앱은 창원을 5개 구(의창·성산·마산합포·마산회원·
  진해)로 다룬다.
- 어댑터(`scripts/adapters/_kosis-core.mjs`, `KOSIS_TO_SGG`)는 창원 값 1개를 **5개 구에 그대로 복제**한다.
- 상관은 `aggregateToSgg`로 시군구 단위에 맞춘 뒤 계산한다. 이 함수는 행정동 코드 앞 5자리로
  묶는데, 창원 5개 구는 `48121·48123·48125·48127·48129`로 **서로 다른 코드**다.
- 결과: 시군구 큐브는 22칸이고, 그중 5칸이 KOSIS 지표에서 **동일한 값**을 갖는다.

### 확인해 줄 것

1. `correlate()`가 실제로 22개 관측으로 피어슨·스피어만을 내는가, 그중 5개가 중복인가.
2. 중복 5점이 계수를 얼마나 끌어당기는가. 창원을 1점으로 접었을 때(n=18)의 계수와 비교해 달라.
   특히 창원이 극단값인 지표(재정자립도 등)에서.
3. 화면 문구 `표본 22개 시군구`가 정직한가. `유의하다`는 표현이 어디서든 나오는가.
4. 스피어만 평균순위(`averageRanks`) 처리는 동점 5개를 올바로 다루는가 — 다루더라도 **독립
   관측이 아니라는 문제**는 남는다는 점을 짚어 달라.
5. 판정: 계수 자체를 18점으로 내려야 하는가, 아니면 22점을 유지하되 고지 문구로 충분한가.
   (내 잠정 의견은 **18점으로 내려야 한다**이고, 표시 단계에서만 접은 것은 부족하다고 본다.
   반박 환영.)

### 관련 파일

```
src/lib/analysis/statistics.ts        correlate / averageRanks / pearsonOf
src/lib/layers/aggregate.ts           aggregateToSgg (코드 앞 5자리로 묶음)
src/lib/layers/stats-view.ts          correlationView / collapseSharedCityRows / cityOf
src/lib/layers/resolve-stats-query.ts unitOf — sggOnly 지표가 끼면 sgg로 내림
scripts/adapters/_kosis-core.mjs      KOSIS_TO_SGG (창원 1:5 복제)
```

## 2. KOSIS 지표를 "율만" 실은 규칙이 실제로 지켜지는가

25개 지표 전부를 **율·지수**로만 골랐다. 근거: 창원 값이 5개 구에 복제되므로 「화재 569건」을
5칸에 넣으면 경남 합계가 창원만 5배 부푼다. 율은 시 전체 값을 구의 대표값으로 쓰고 그 사실을
적으면 정직하다.

### 확인해 줄 것

1. `scripts/adapters/kosis-indicators.mjs`의 `KOSIS_LAYER_SPECS` 25개 중 **건수·합계 성격이 섞인
   것이 하나도 없는가.** 이름은 율인데 실제 KOSIS 항목이 건수인 경우를 특히 의심하라
   (`itmId: "T10"` 지정이 실제로 율 항목을 가리키는지).
2. `src/lib/layers/kosis-catalog.ts`가 모든 KOSIS 지표에 `aggregation: "weightedAvg"`를 주는데,
   **경남 전체 평균**을 낼 때 창원이 5번 세어지지 않는가. `weightKey`가 없으면 가중치가 1이라
   단순 평균이 되고, 그러면 창원이 5/22 = 22.7% 가중을 갖는다(실제 인구 비중은 약 30%지만
   그것은 우연이다).
3. 커버리지 검사: 22개 시군구 중 몇 곳에 값이 있는가. 12/22짜리 표는 뺐다고 했는데 실제로
   전부 22/22인지.
4. 연도 정합성: 한 레이어 안의 지표들이 **같은 연도**를 쓰는가. 다르면 "2024년 화재율과
   2022년 재정자립도의 상관"이 나온다.

### 관련 파일

```

scripts/adapters/_kosis-core.mjs       fetchKosisTable / toSggYearMap / expandToDongCells
src/lib/layers/kosis-catalog.ts        kosisLayer 팩토리
src/lib/layers/catalog.ts              CUBE_LAYERS / NL_LAYERS / PRIVATE_LAYERS
public/data/layers/                    실제 생성된 레이어 JSON (값을 직접 열어 보라)
```

## 3. [신규] 지점 반경 분석의 기하 계산

가장 최근에 붙인 기능이라 실전 검증이 가장 적다. 지도 아무 곳이나 클릭하면 그 지점이 속한
행정동, 반경 안 의료시설, 원에 걸치는 행정동을 낸다.

### 내가 한 주장 — 각각 참인지 확인해 달라

| # | 주장 | 근거로 댄 것 |
|---|---|---|
| 3-1 | 광선 교차법이 305개 실제 행정동에서 옳게 판정한다 | 시청 좌표 2곳, 경남 밖 2곳 |
| 3-2 | 구멍(도넛)을 올바로 처리한다 | 인공 도넛 고정물 |
| 3-3 | 외곽 상자 거리는 실제 경계 거리의 **하한**이라 걸러내기가 안전하다 | 수학적 논증만. 검사는 개수 고정 |
| 3-4 | 위경도를 평면으로 펴서 재도 몇 km 규모에서 오차가 미터 아래다 | 검증 안 함 ← **여기를 봐 달라** |
| 3-5 | 반경 안 인구·소비 **합계를 내지 않는 것**이 옳다 | 면적 비례 배분 가정이 거짓이라는 논거 |

### 특히 파 봐야 할 곳

- **3-4의 근사 오차.** `segmentDistanceKm`은 `latScale = 110.574`, `lngScale = 111.32·cos(lat)`로
  등거리 원통 투영을 쓴다. 위도 35°, 반경 3km에서 하버사인 대비 오차가 몇 m인가? 반경 경계에
  걸친 시설·행정동의 포함 여부가 뒤집힐 만한 크기인가?
- **3-3의 하한 주장.** 지점이 bbox **안**에 있는데 폴리곤 밖인 경우(예: 활처럼 휜 해안 읍면)
  거리가 0으로 걸러져 통과한다 — 그건 안전한 쪽이다. 반대로 **빠뜨리는** 경우가 정말 없는가?
  경도 스케일을 `point.lat` 기준으로 잡는데, 상자가 남북으로 길면 상자 반대편의 실제 경도
  거리는 더 짧아진다. 하한이 깨질 수 있는가?
- **`cityOf` 정규식.** `/^(.+?시)\s*[가-힣]+구$/`. 경남에 「…시 …구」 꼴이 창원 5개뿐인가?
  전국 확장 시 「성남시 분당구」는 되는데 「세종특별자치시」류는? 비탐욕 `.+?`가 「창원시마산합포구」를
  「창원시」로 자르는 게 맞는가(마산합포구에 「시」가 없으니 맞지만, 「부천시원미구」류의 옛 이름은?)
- **성능.** 305개 폴리곤 · 꼭짓점 95,660개를 클릭마다 훑는다. 상자 걸러내기 후 실제 몇 개가
  남는가? 모바일 저사양 기기에서 클릭 반응이 몇 ms인가?

## 4. 이상치 판정(MAD)이 22개 표본에서 뜻이 있는가

중앙값절대편차(MAD)의 3배를 넘으면 이상치로 본다. 평균±표준편차를 안 쓴 이유는 이상치가
표준편차를 함께 키워 스스로를 정상 범위 안에 넣기 때문이다.

### 확인해 줄 것

1. `(0.6745 · (x − median)) / MAD` 의 0.6745는 **정규분포 가정**에서 나온 상수다. 시군구 22개
   지표가 정규분포에 가까운가? 아니라면 「3배」의 뜻이 무엇인가?
2. 표본 22개에서 MAD 기반 이상치 검출의 검정력. 22개 중 5개가 중복(1번 항목)이면 중앙값과 MAD가
   창원 값 쪽으로 끌려가지 않는가?
3. `MAD === 0` 가드가 있다(절반 이상이 같은 값). 이 경우 화면은 "자료가 없는 것이 아니다"라고
   말한다 — 이 문구가 사용자에게 옳게 읽히는가?
4. 읍면동 단위(305칸) 이상치는 어떤가. 시군구 지표를 305칸으로 펴면 같은 값이 14번 복제되는데,
   `unitOf`가 그 경우를 정말 다 잡아 sgg로 내리는가?

### 관련 파일

```
src/lib/analysis/statistics.ts    findOutliers / quantile
src/lib/layers/stats-view.ts      outlierView
tests/analysis/statistics.test.ts
```

## 5. RAG 검색 품질 — 15개 평가셋이 근거가 되는가

지표 이름을 한 번도 쓰지 않은 말 15개로 재서 1위 적중이 4/15 → 10/15, 5위 안 11/15 → 15/15가 됐다.

### 의심 지점

- **평가셋이 15개다.** 내가 만들었고, 고치면서 봤다. 과적합이 아니라고 말할 근거가 있는가?
- **`specificity = 0.65`** — 레이어 청크에 매기는 감점 계수. 0.8은 부족했고 0.65로 정했는데,
  이 값은 **평가셋을 보고 고른 값**이다. 다른 질의에서 지표를 과도하게 띄우지 않는가?
- **동의어를 하나 뺐다.** 「의사·병원」 확장이 「병원이 부족한 동」에서 공공 의료취약 도구를
  3위 밖으로 밀어냈다. 빼니 1위가 9→10으로 올랐다. 이 **제거**가 다른 질의를 망가뜨리지 않는가?
- 조사 제거(`stripParticle`)가 「빚」·「불」·「차」 같은 1글자 토큰을 살렸는데, 반대로 잘못 자르는
  말이 있는가? (「이」·「가」로 끝나는 명사)

### 부탁

**당신이 직접 20~30개 질의를 새로 만들어 재 달라.** 내 평가셋을 보지 말고 만들어야 뜻이 있다.
경남 공무원이 실제로 칠 법한 말로. 결과가 내 숫자보다 나쁘면 그게 참값이다.

### 관련 파일

```
src/lib/rag/retrieve.ts        하이브리드 점수 / QUERY_SYNONYMS / specificity
src/lib/rag/tokenize.ts        PARTICLES / stripParticle
src/lib/rag/                   청크 생성부
tests/rag/retrieval-quality.test.ts   내 15개 평가셋(먼저 보지 말 것)
```

## 6. 결손을 좋은 값으로 메우고 있지 않은가 (전역 훑기)

이 저장소의 오래된 결함 유형이다. `?? 0`·`catch(() => null)`이 **안전한 쪽**이면 자료 결손이
정상으로 인쇄된다.

### 부탁

`?? 0`, `?? []`, `catch`, `|| 0`, `Number(x) || 0` 를 전수로 훑어, **없는 값이 좋은 값으로 보이게
되는 자리**를 찾아 달라. 특히:

- `aggregate.ts`의 `sum` 경로: `total += m.series[key]?.[i] ?? 0` — 22개 중 3개가 없는데 합계가
  나오면 그 합계는 거짓이다.
- KOSIS 어댑터의 재시도 3회 실패 경로.
- 상류 응답을 **개수**로 판정하는 자리(정상 코드로 반쪽 자료를 주는 외부 API).

## 7. 배포본과 코드가 같은 말을 하는가

로컬 초록은 증거가 아니다. 이 앱에서 실제로 겪은 일: 창원 접기가 검사는 통과하고 배포본에서는
헛돌았다.

### 부탁

<https://ralphton-ai-gis-copilot.vercel.app/> 에서 직접:

1. 「재정자립도와 빈집 비율의 상관관계」 → 표본 수·단위 문구·창원 표기를 화면에서 확인.
2. 「화재 많은 시군구」·「빈집 많은 시군구」 → KOSIS 레이어 도달 확인.
3. 지도에서 「지점 분석」을 켜고 아무 곳이나 클릭 → 행정동 이름이 맞는가(다음 지도 서비스와 대조).
   바다 위·부산 쪽도 눌러 보라.
4. 아무 순위 결과에서 A4 보고서를 내려받아 **인쇄 미리보기**로 확인 — 표 머리글이 둘째 쪽에도
   나오는가, 행이 쪽 경계에서 잘리는가, 다크 테마 색이 종이에 묻어 나오는가.
5. 콘솔 JS 에러 0인지.
