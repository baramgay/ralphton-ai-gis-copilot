배포본 https://gnbc.site 에서 실측한 것만 적는다. 게이트(`npm run verify`)와 배포 검사 8종은
전부 초록이었다. **초록불이 못 보는 자리만 모았다.**

핀 복원(`68e6109`)은 확인했다 — 「창원시 병원 위치」에 점이 생기고 「지도 시설 900개 표시 ·

우선순위 순이다. **1번이 가장 급하다 — 산출물이 밖으로 나가면 되돌릴 수 없다.**

## 1. 합성 인구가 산출물에 「실데이터」로 실린다 (최우선)

### 증상

배포본에서 「고령화율이 높은 곳」을 묻고 CSV를 내려받은 실물이다.

```
제목,고령화율이 높은 지역
기준월,2026-06
데이터모드,live
출처,supabase-cache
내보낸시각,2026-09-06T14:26:25.421Z

순위,행정동코드,시도시,이름,값,비고
1,4817032000,경남,진주시 정촌면,24.92%,고령화율 · 24.92%
2,4825025000,경남,김해시 진영읍,24.88%,고령화율 · 24.88%
3,4812953000,경남,창원시진해구 충무동,24.85%,고령화율 · 24.85%
```

이 표의 값은 **합성값이다.** 스냅샷을 직접 열어 확인한 수치:

- 305개 행정동 인구 합계 **13,256,410명** — 실제 경상남도는 약 325만 명이다. 4배다.
- 고령화율 범위 **7.12% ~ 24.92%**. 상한이 24.92에서 잘려 있다. 실제로는 합천·의령·남해가
  40%를 넘고 창원 신도시가 12~14%다. 상위 11곳이 24.92~24.29% 안에 몰려 있다 —
  **줄을 세워 놓았지만 순위가 노이즈다.**

코드도 이 사실을 안다. 화면 배너는 「시설만 실데이터입니다 — 인구·세대는 기준 스냅샷입니다」,
「인구·세대·출생·사망은 합성값이라 대외 수치로 인용하지 마세요」라고 정확히 적는다.

**그런데 배너만 안다.** 배너는 화면에 남고, 산출물은 밖으로 나간다.

### 원인

`snapshot.mode === "live"` 하나만 보고 「실데이터」라고 적는 자리가 여섯 곳이다.
어느 항목이 실측인지 가리지 않는다.

| 자리 | 현재 |
|---|---|
| `src/components/copilot/copilot-app.tsx:4781` | 결과 패널 출처 칩 — mode 가 live 면 「실데이터」 |
| `src/lib/analysis/export-a4.ts:41` | A4 인쇄 보고서 머리글 — 같은 판정 |
| `src/lib/analysis/export-csv.ts:90` | 데이터모드 칸에 mode 원값 |
| `src/lib/analysis/export-csv.ts:122` | 데이터모드 칸에 mode 원값 |
| `src/lib/analysis/export-report.ts:91` | 「- 데이터모드: live」 |
| `src/lib/analysis/export-hwp.ts:37` | 「데이터모드: live」 |

판단 도구는 **이미 있다.** `src/lib/analysis/data-mode.ts` 의 `populationIsLive(mode, sourceNotes)`
와 `dataModeLabel(...)`(→ 「실데이터」 또는 「시설 실데이터」)이 그것이다. 배너는 이것을 쓰고
위 여섯 자리는 안 쓴다. `export-a4.ts:33` 의 주석은 「공공기관 보고서에 영문 상태값이 실린다」는
바로 이 함정을 이미 적어 두었는데, 정작 고친 것은 영문뿐이고 **무엇이 실데이터인가는 안 갈랐다.**

### 할 일

1. **결과 패널 출처 칩**(`copilot-app.tsx:4781`)이 `dataModeLabel(snapshot.mode, snapshot.sourceNotes)`
   를 쓰게 한다. 인구가 합성이면 「시설 실데이터」로 적힌다.

2. **산출물 네 갈래**(A4·CSV·보고서·HWP)에 mode 원값 대신 사람이 읽는 말을 싣는다.
   각 export 함수에 `sourceNotes`(또는 이미 가른 결과값)를 넘겨야 한다 — mode 하나로는
   가를 수 없다. 호출부는 `copilot-app.tsx:2137`·`2155`(CSV), `2182`(보고서 입력)다.

3. **인구에서 나온 순위를 내보낼 때는 합성값임을 산출물 안에 적는다.** 화면 배너의 문장이
   정본이다: 「인구·세대·출생·사망은 합성값이라 대외 수치로 인용하지 마세요.」
   해당 지표는 고령화율·인구밀도·1인가구 비중·자연증가·출생·사망·총인구 등 인구 파생 전부다.
   시설·KOSIS·SKT·NH·KCB 에서 나온 순위에는 붙이지 않는다 — 그쪽은 실측이다.

4. 「출처, supabase-cache」처럼 **내부 저장소 이름을 산출물에 적지 않는다.** 사람이 읽는 말로
   바꾸거나 그 줄을 뺀다. 「데이터모드, live」도 마찬가지다.

## 2. 출처 노트가 자기 자료를 가짜라고 말한다

### 증상

배포본 왼쪽 패널 「출처 노트」를 펼치면 여섯 줄이 나오고, 그게 전부다.

```
· 경상남도 행정동 경계를 기준으로 만든 결정론적 시연 데이터입니다.
· 인구·세대·출생·사망 값은 합성값이며 실제 주민등록 통계가 아닙니다.
· 시설 위치는 행정동 내부 대표점 주변 PRNG 배치이며 실제 요양기관 좌표가 아닙니다.
· 진료과·운영시간 null은 UI의 '데이터 없음' 처리를 검증하기 위한 의도적 값입니다.
· 실데이터 연결 시 시설은 HIRA 병원정보(v2), 인구는 행정안전부 주민인구 API를 사용합니다.
· 분석 거리는 행정동 대표점 기준 직선거리이며 도로·대중교통 접근성과 다를 수 있습니다.
```

세 번째 줄이 거짓이다. 시설 4,272곳은 **실좌표다.** 스냅샷에서 뽑아 실제 위치와 대조했다.

| 시설 | 스냅샷 좌표 | 판정 |
|---|---|---|
| 경상국립대학교병원 | 35.1759944 / 128.0964924 | 일치 |
| 학교법인성균관대학삼성창원병원 | 35.2424957 / 128.5923771 | 일치 |
| 경상남도마산의료원 | 35.1992371 / 128.5655967 | 일치 |

### 원인

`src/lib/data/live-sync.ts:290` 의 `rewriteSyntheticNote` 는 **인구 각주만** 다시 쓴다.
시설 PRNG 각주와 「결정론적 시연 데이터」 각주는 손대지 않고 live 스냅샷으로 넘어간다.

그리고 갱신 사실을 적은 각주 두 줄은 배열 **뒤에 붙는다**:

```
7. HIRA 병원정보서비스(v2)로 경남 시설 4272곳을 갱신했습니다.
8. 인구·세대 시계열은 검증된 기준 스냅샷을 유지합니다.
```

화면은 `snapshot.sourceNotes.slice(0, 6)`(`copilot-app.tsx:4375`)만 그린다. **7·8번이 잘린다.**
그래서 사용자가 보는 여섯 줄은 전부 「시연·합성·PRNG」이고, 실측이 되었다는 사실은 화면 어디에도
없다. 1번과 정확히 반대 방향의 같은 결함이다 — 한쪽은 가짜를 진짜라 하고, 한쪽은 진짜를 가짜라 한다.

### 할 일

1. `rewriteSyntheticNote` 가 **시설 각주도** 다룬다. HIRA 교체가 성공했으면
   「시설 위치는 … PRNG 배치이며 실제 요양기관 좌표가 아닙니다」를 지운다.
   실패해서 기준 스냅샷 좌표를 그대로 쓰면 그 줄은 남겨야 한다 — 사실이 정한다.

2. 「경상남도 행정동 경계를 기준으로 만든 결정론적 시연 데이터입니다」도 같다.
   live 에서 이 문장이 그대로 남으면 전체를 시연이라 말하는 것이 된다.
   무엇이 아직 시연인지만 말하도록 다시 쓴다.

3. **「진료과·운영시간 null은 UI의 '데이터 없음' 처리를 검증하기 위한 의도적 값입니다」를 지운다.**
   null·UI·「검증하기 위한」은 만든 사람의 말이지 쓰는 사람의 말이 아니다. 이 각주는
   사용자 화면에 그대로 나온다. 남길 값이 있으면 「진료과·운영시간이 제공되지 않는 시설이 있습니다」
   같은 사실 문장으로 바꾼다.

4. `slice(0, 6)` 을 없앤다. 여섯 줄이 상한일 이유가 없고, 하필 **잘리는 쪽이 갱신 사실**이다.
   길면 접어 두되 자르지는 않는다.

## 3. 요청하지 않아도 지도에 병원 점이 뜬다

### 증상

배포본에서 지도 마커 수를 셌다.

| 화면 | 지도 위 마커 |
|---|---|
| 첫 화면(거창군 북상면 선택) | 0 |
| 「창원시 병원 위치」 | 1(군집) + 「900개 표시 · 전체 1,361」 |
| **「고령화율이 높은 곳」** | **2** |
| **「의령군 보건소 어디」** | **10** |

「고령화율이 높은 곳」은 시설을 묻지 않았다. 그런데 점이 뜬다.

### 원인

`copilot-app.tsx:1928` 의 `loadLivePlacesNearSelection` 이 **선택 지역이 바뀔 때마다**
카카오 장소 API 로 「병원」 10곳을 받아 온다(`useEffect`, 키워드가 「병원」으로 고정).
그 결과가 `livePlaces={livePlaces}`(`copilot-app.tsx:4406`)로 지도에 그대로 넘어가고,
`kakao-map.tsx:617` 이 **아무 조건 없이** 마커로 그린다.

```tsx
for (const place of livePlaces.slice(0, 20)) {
  const marker = new maps.Marker({ ... });
  marker.setMap(map);
}
```

시설 핀은 `showFacilities={analysis.isFacilityResult}` 로 잠갔는데, **점을 그리는 두 번째 경로는
잠기지 않았다.** 앞 지시서 7절에 「`livePlaces` 가 이미 두 번째 지점 경로이니 세 번째를 만들지
마라」고 적은 그 경로다.

덤으로, 지도 위에서 스냅샷 시설(심평원 자료)과 카카오 실시간 장소가 **생김새로 구분되지 않는다.**
출처가 다른 두 가지가 같은 점으로 보인다.

### 할 일

1. **`livePlaces` 마커도 「물었을 때만」 그린다.** 시설 핀과 같은 조건 아래 둔다 —
   `analysis.isFacilityResult` 가 참일 때만 지도로 넘긴다. 오른쪽 목록(`copilot-app.tsx:5154`)에
   남기는 것은 사용자가 그 패널을 열었을 때 보는 것이니 지금대로 두어도 된다.

2. **선택 지역이 바뀔 때마다 외부 API를 부르지 않는다.** 시설을 묻지도 않았는데 카카오 장소
   조회가 나가고 있다. 시설을 물었을 때만 부른다.

3. 그려야 할 때는 **스냅샷 시설과 다르게 보이게** 한다. 앞 지시서 7절에서 정한
   `kind` 별 색·범례를 쓰고, 실시간 검색 결과임을 범례에 적는다. 같은 점으로 두면 심평원 자료와
   카카오 검색 결과가 한 덩어리로 읽힌다.

## 4. 약국은 자료가 0인데 기능으로 안내한다

### 증상

「창원시 약국 위치」 → **0개 시설**. 화면 문구는 「요청 조건(약국)에 해당하는 시설 데이터가 현재
스냅샷에 없습니다」. 문구 자체는 정직하다. 문제는 **그 질문을 제품이 먼저 권한다**는 것이다.

스냅샷 4,272곳 종류별 실측:

```
의원 1,748 · 치과의원 966 · 한의원 794 · 보건소 414 · 병원 213 · 요양병원 112 · 종합병원 25
약국 0
```

HIRA 병원정보서비스(v2)에는 약국이 없다. 약국은 별도 자료다. 운영시간도 전 시설이 비어 있어
「야간 진료 병원」 역시 0개다.

그런데 제품은 약국을 정식 기능으로 설명하고 예시로 권한다.

| 자리 | 내용 |
|---|---|
| `src/lib/analysis/glossary.ts:158` | 「약국은 따로 요청할 때만 의료기관에 포함합니다.」 |
| `src/lib/analysis/query-catalog.ts:418` | 예시 「약국만 보여줘」 |
| `src/lib/analysis/query-catalog-meta.ts:106` | 「약국만 보여줘」 |
| `src/lib/analysis/query-catalog-meta.ts:116` | 「주말 여는 약국」 |
| `query-catalog.ts:30-39`, `query-rules.ts:130` 등 | 약국 분기 로직 일체 |

없는 자료를 다루는 규칙을 용어집에서 설명하고, 그 질문을 예시로 올리고, 누르면 0건이 나온다.

### 할 일

둘 중 하나를 고른다. **섞지 않는다.**

- **길 A(권함) — 지금은 없다고 말한다.** 예시 목록에서 「약국만 보여줘」·「주말 여는 약국」·
  「야간 진료 병원」을 뺀다. 용어집의 약국 규칙 문장을 「약국은 현재 자료에 포함되지 않습니다」로
  바꾼다. 활용 데이터 목록(`src/lib/analysis/data-inventory.ts`)에도 무엇이 안 실렸는지 적는다.
  분기 로직은 지운다 — 자료가 들어오면 그때 다시 넣는다.

- **길 B — 약국 자료를 넣는다.** 약국 자료를 실제로 실은 뒤에만 지금 문구를 유지한다.
  이 지시서의 범위 밖이다. 길 B를 고르려면 먼저 말해라.

운영시간(야간·주말)도 같은 판단을 받는다. 전 시설이 비어 있으면 그 질문은 예시에서 뺀다.

## 5. 시설 결과에 계산하지 않은 산식이 방법론으로 붙는다

### 증상

「창원시 병원 위치」 → 시설 1,361곳 목록. 그 아래 방법론 줄:

```
방법론 · 의료 접근성 취약지수 = 공급 부족 35% + 고령 수요 25% + 최근접 거리 25%
        + 2km 무시설 15%. 거리=행정동 대표점 직선거리. 자연증가=출생−사망(전입·전출 제외).
```

취약지수는 그 결과에서 **쓰이지 않았다.** 목록을 뽑았을 뿐이다.
「의령군 보건소 어디」(22곳)·「치과 많은 곳」(966곳)·「야간 진료 병원」(0곳)도 전부 같다.

### 원인

`copilot-app.tsx:3300`

```tsx
: analysis && !analysis.isFacilityResult && analysis.formulaNotes.length > 0
  ? analysis.formulaNotes.join(" · ")
  : METHOD_SUMMARY;
```

`isFacilityResult` 면 그 결과가 가진 `formulaNotes` 를 **버리고** 기본값 `METHOD_SUMMARY`
(= 취약지수 산식)로 떨어진다.

### 할 일

시설 목록 결과에는 목록을 뽑은 방법을 적는다 — 어떤 종류를 어떤 범위에서 골랐는지.
계산하지 않은 산식을 방법론에 적지 않는다. 적을 것이 없으면 그 줄을 빼는 편이 낫다.
공공기관 산출물에서 방법론 오기는 값이 틀린 것과 같은 무게다.

## 6. 옛 도메인 잔재

정본 주소는 **https://gnbc.site** 다. 옛 주소가 남은 자리:

| 자리 | 성격 |
|---|---|
| `README.md:5` | 「프로덕션: https://ralphton-ai-gis-copilot.vercel.app」 |
| `src/app/evaluator/page.tsx:119` | **사용자 화면에 옛 주소를 적어 보여 준다** |
| `src/app/api/kakao/sdk/route.ts:32` | 카카오 SDK Referer 폴백 |
| `scripts/verify-*.mjs` 9종 | 인자를 안 주면 옛 주소를 잰다 |
| `scripts/prod-checks/*.mjs` 약 20개 | 주소가 상수로 박혀 있음 |

지금은 옛 주소가 같은 배포를 서비스해서 검사가 초록이다. **그래서 위험하다** — 두 주소가 갈라지는
순간, 검사는 아무 소리 없이 옛 주소를 재고 초록을 낸다.

### 할 일

1. 검사 스크립트의 기본 주소를 `https://gnbc.site/` 로 바꾼다. `scripts/prod-checks/*` 도 같다.
2. `evaluator` 화면과 `README.md` 를 정본 주소로 고친다.
3. 카카오 Referer 폴백도 정본 주소로 바꾼다.

## 완료 판정

npm run verify
node scripts/verify-stats-prod.mjs      https://gnbc.site/ ; echo exit=$?

파이프로 넘기지 마라. 게이트를 파이프에 태우고 `&&` 로 이으면 붉은 게이트로도 다음 단계가 돈다.
로그로 빼고 **종료 코드로** 판정한다.

### 눈으로 확인할 것 (배포본)

1. 「고령화율이 높은 곳」 → CSV 를 내려받아 **live 도 supabase-cache 도 없고**, 인구가
   합성값이라는 사실이 파일 안에 적혀 있다.
2. 같은 질의의 A4 보고서 머리글이 「실데이터」라고 단정하지 않는다.
3. 같은 질의의 결과 패널 칩이 「시설 실데이터」로 적힌다. 반대로 「재정자립도와 빈집 비율
   상관관계」(KOSIS 실측)에서는 「실데이터」 그대로다 — **둘이 갈리는지**가 판정선이다.
4. 「출처 노트」에 PRNG 문장이 없고, HIRA 갱신 문장이 **잘리지 않고 보인다.**
5. 「고령화율이 높은 곳」에서 지도 마커가 **0개**. 「창원시 병원 위치」에서는 점이 뜨고
   「900개 표시 · 전체 1,361」이 함께 뜬다.
6. 예시 목록에 약국·야간·주말이 없다. 용어집에 약국 규칙 문장이 없다.
7. 「창원시 병원 위치」의 방법론 줄에 「취약지수 = 공급 부족 35% …」가 없다.

### 가드를 깨뜨려 보기

1번을 막는 검사를 새로 넣었다면, **일부러 되돌려 붉은불이 나는지 본다.** 초록불은 「위반 없음」과
「검사가 못 봄」을 구분하지 못한다. 결과 칩을 옛 판정으로 되돌렸을 때 검사가 붉어지지 않으면
그 검사는 아무것도 안 재고 있다.

## 규칙

- 「읍면동」 금지. **「행정동」**만 쓴다. 주석·문자열·산출물 전부. `tests/analysis/unit-word.test.ts` 가 막는다.
- 색은 테마 토큰으로. 새 Tailwind 색 유틸리티를 쓰지 마라 — 테마 전환은 유틸리티를 하나씩
  열거해 덮는다. 열거에 없는 클래스는 조용히 바탕에 묻힌다(빌드·lint 전부 초록).
- 산출물·화면에 만든 사람의 말을 쓰지 마라. 파일 경로·환경변수·null·live·supabase-cache·
  「UI 검증용」 같은 말은 읽는 사람에게 뜻이 없다.
- 증상만 덮지 마라. 재현 → 원인 → 수정 → 배포본 검증.
- 한 자리를 고쳤으면 **같은 모양의 다른 자리를 전수 확인한다.** 1번이 여섯 자리인 이유가 그것이다.
- 커밋 전 `git fetch` 로 `HEAD..origin/main` 이 0인지 본다.
