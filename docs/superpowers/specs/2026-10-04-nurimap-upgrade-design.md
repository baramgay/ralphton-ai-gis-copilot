# 누리맵 기능·UI/UX 고도화 제안

작성일: 2026-10-04. 상태: 사용자 병렬 진행 요청에 따라 1차 개선안을 구현했다. 아래 문제 목록은 변경 전 실측 기록이며, 배포·검증 결과는 `docs/nurimap-operations.md`에 기록한다.

## 목적과 전제

기존 공간 분석 기능과 SKT·NH·KCB 자료를 유지하면서, 처음 방문한 사용자가 분석을 시작하고 결과를 이해하는 과정을 개선한다. 주 사용자는 지자체·공공기관 실무자로 가정하며 사용자 답변에 따라 설명 수준을 조정한다. 새로운 회원제나 결제 기능은 이번 범위에 포함하지 않는다.

운영 URL은 https://gnbc.site/, 저장소는 `baramgay/ralphton-ai-gis-copilot`, 로컬 경로는 `C:\업무\랄프톤`이다. Vercel 프로젝트는 `ralphton-ai-gis-copilot`, 연결된 Supabase 프로젝트는 기존 서비스와 공유하는 `eum-jido`다. 기존 공유 데이터와 다른 서비스 테이블은 변경하지 않는다. 기존 미추적 파일 `scripts/adapters/nh-blocks.mjs`는 이번 작업과 별개다.

## 직접 확인한 문제

1. 1254×566 첫 진입 화면에서 시작 안내가 지도를 크게 가린다. 화면 폭 1280px까지 모바일 바텀시트를 사용해 작은 노트북에서도 결과를 별도로 열어야 한다.
2. 분석 전 결과는 0개인데 거창군 북상면 상세 수치가 자동으로 선택된다. 합성 인구 수치가 지역 상세에 표시되므로 사용자가 실제 지역 통계로 오인할 수 있다.
3. '생활인구 많은 동네' 실행 후 305개 행정동 순위는 정상 산출된다. 결과 기준월은 2025-12지만 해석 요약에 2026-06이 표시된다.
4. 390×844 화면에서 가로 넘침은 없다. 다만 질의 안내·최근 질문·범례가 지도 상단에 몰려 지도와 겹친다.
5. Supabase 게시 스냅샷은 행정동 305개, 의료시설 4,262개다. `source_notes`는 인구·세대·출생·사망을 합성값으로 명시한다.
6. 스냅샷 생성일은 2026-07-18, 갱신일은 2026-09-07이다. 읽기 코드가 `created_at`으로 정렬하고 공개 시각도 생성일을 사용하므로 같은 ID를 갱신해도 신선도 계산에 반영되지 않는다.
7. 운영 `/api/health`의 동기화 상태는 `failed`, 마지막 시도는 2026-09-08이며 중단 오류를 기록한다. 파일·인스턴스 메모리에 상태를 저장하는 구현은 Vercel 인스턴스 간 일관성을 보장하지 않는다. 현재 응답만으로 이후 모든 Cron 실행이 실패했다고 단정할 수는 없다.
8. Cron 인증에는 `CRON_SECRET`이 없을 때 외부에서 지정 가능한 `x-vercel-cron` 헤더를 신뢰하는 분기가 있다. 실제 비밀값 검증으로 통일해야 한다.
9. 누리맵의 `data_snapshots`, `region_metrics`, `ai_gis_facilities` 테이블에는 RLS가 활성화되어 있다.

## 접근 방식 비교

| 방식 | 장점 | 제약 |
| --- | --- | --- |
| 기존 앱의 핵심 흐름 개선 — 권장 | 분석 자산을 유지하며 UX와 데이터 신뢰 문제를 함께 해결한다 | 이번 단계는 기존 기능의 완성도에 집중한다 |
| 시각 스타일만 변경 | 수정 범위가 작다 | 기준월·합성값·동기화 문제를 해결하지 못한다 |
| 앱 전면 재구축 | 구조와 기능을 새로 설계할 수 있다 | 검증된 GIS·내보내기 기능을 다시 검증해야 해 회귀 위험과 작업량이 크다 |

## 1차 구현 범위

### 첫 진입과 지도 탐색

- 시작 안내를 짧은 카드로 줄이고 추천 질문에서 바로 분석을 시작할 수 있도록 한다.
- '조작' 등의 문구를 사용자 행동을 설명하는 표현으로 정리한다. 기존 접근성 이름과 테스트도 함께 조정한다.
- 분석 전에는 시작 안내와 선택 방법을 보여 주고 임의 지역 상세 및 빈 결과용 내보내기 버튼을 노출하지 않는다.
- 작은 데스크톱에서도 지도와 결과를 같이 확인하도록 화면 폭·높이에 맞는 패널 배치를 검토한다. 태블릿과 모바일은 바텀시트를 유지한다.
- 모바일에서 질의 피드백·최근 질문·범례가 겹치지 않도록 위치와 표시 우선순위를 정리한다.
- 기존 밝은 화면·다크·고대비·키보드 조작을 유지하며 본문 크기와 터치 영역을 확인한다.

### 분석 결과의 이해

- 결과는 핵심 결론, 현재 지표·단위·기준월·출처, 순위, 지역 상세 순서로 읽힌다.
- 해석 요약의 기준월은 분석에 실제 사용한 자료를 따른다. 혼합 자료는 서로 다른 기준월을 명시한다.
- 합성 인구·세대·추세에는 해당 수치 가까이에 시연 자료임을 표시한다. 의료시설과 민간 실측 자료까지 합성으로 표시하지 않는다.
- 결과 없음, 자료 로딩, 분석 실패, 주변 장소 없음 상태를 구분한다. 이용자 화면에는 REST 키 등 운영 설정 대신 사용 가능한 다음 행동을 제시한다.
- 공유 링크와 표·보고서는 선택한 지표·지역·기준월을 동일하게 재현해야 한다.

### Supabase와 Vercel 운영 안정성

- 최신 게시 스냅샷은 `updated_at` 기준으로 선택하며 생성 시각과 갱신 시각을 구분한다. 관련 API 헤더와 신선도 계산을 함께 수정한다.
- 동기화 실행 상태는 누리맵 전용 Supabase 저장소에 영속화한다. 스키마가 필요하면 마이그레이션과 제한된 권한을 함께 추가한다. 공개 응답에는 비밀값이나 내부 오류 세부를 노출하지 않는다.
- Cron은 검증된 Bearer 비밀값 또는 기존 수동 동기화 비밀값으로만 실행된다.
- 데이터 조회·동기화 실패 시 마지막 정상 게시 자료를 유지하며 실패와 미게시를 성공으로 기록하지 않는다.
- 기존 Vercel 프로젝트의 Preview에서 화면과 API를 검증한 뒤 운영 반영 결과를 확인한다. Cron 시간과 실행 상한 변경 여부는 실패 원인을 추가 확인한 후 결정한다.

## 검증과 성공 기준

- 390×844, 768×1024, 1280×800, 1440×900에서 가로 넘침 없이 질의·지역 선택·결과 열기에 접근할 수 있다.
- 첫 방문에서 추천 질문 한 번으로 분석 실행과 결과 표시까지 이어진다.
- 분석 전 임의 지역의 수치를 보여 주지 않는다. 합성값 표시는 실제 지역 선택 후에도 수치 가까이에서 확인할 수 있다.
- 생활인구·카드매출·소득·유입인구 질의의 지도, 순위, 해석, 내보내기 기준월이 일치한다.
- 새로고침 및 공유 링크 진입 후 같은 분석 상태가 복원된다.
- 같은 스냅샷 ID를 갱신했을 때 갱신 시각과 신선도가 달라지며 최신 갱신 자료를 선택한다.
- 인증 없는 Cron과 위조 Cron 헤더는 401을 반환한다. 정상 인증 호출은 기존 분석·게시 정책을 지킨다.
- 다른 실행 인스턴스에서도 저장된 동기화 상태를 읽을 수 있다. 실패 및 미게시가 최근 성공으로 기록되지 않는다.
- 관련 단위·API·UI 테스트, 타입 검사, 린트, 프로덕션 빌드, 브라우저 검증을 통과한다.

## 추가 논의가 필요한 별도 작업

주 사용자 확정은 설명 수준과 기본 화면에 반영한다. 사용자 계정·개인별 저장, 신규 실측 인구자료 수급, 블록별 카드매출 공개 정책은 각각 요구사항과 데이터 권한을 확정한 뒤 별도 범위로 진행한다.
