# 누리맵 신뢰도와 사용자 경험 전면 개편

사용자는 남은 검색·실데이터·임베딩·운영 검증 개선을 모두 요청하고, 현재 UI에 대폭 개선이 필요하다는 전제로 레이아웃까지 전면 개편하도록 지시했다. 기존 기능과 결과의 정확성을 유지한다는 조건은 기존 화면 구조를 유지한다는 뜻이 아니다.

## 사용자 경험

첫 진입에서 질문할 수 있는 주제와 데이터의 범위를 이해하고 질문을 실행할 수 있어야 한다. 결과에서는 분석 대상 지역, 지표와 단위, 기간, 첫 결과와 근거가 먼저 읽혀야 한다. 지도와 결과 선택이 연결되고 지역 비교, 조건 변경, 공유 및 내보내기를 찾을 수 있어야 한다. 모바일에서는 화면을 가리는 패널보다 명확한 지도·결과 전환을 우선한다. 자세한 옵션과 설명은 필요한 시점에 펼친다. 실제 화면을 캡처해 구조와 밀도를 점검하며 작은 화면, 키보드, 로딩·빈 결과·오류 상태를 검증한다.

## 검색과 데이터

고령 수요 대비 의료 공급과 일시 체류 유입을 전입 및 일반 의료 취약과 구별한다. 기존 고정 평가의 정답은 바꾸지 않고 독립 의역·대조 사례를 추가한다. 명시 지표 우선순위와 무근거 차단을 보존한다.

인구·가구·출생·사망은 접근 가능한 공식 출처에서 지역 코드, 관측 기간, 단위, 결측과 집계 관계를 검증한 값만 연결한다. 확보하지 못한 지표나 세부 지역은 합성 값을 공식 통계로 바꾸어 표시하지 않는다. 필요한 자격이나 자료가 없으면 그 사실과 재현 가능한 연계 절차를 기록한다.

## 원격 임베딩

원격 응답의 순서, 개수, 유한 수치, 차원 및 유효 벡터를 검사한다. 캐시는 제공자·모델·코퍼스 내용에 따라 분리하고 제공자 배치 제한을 고려한다. 원격 장애에서는 기존 로컬 근거를 유지한다. 실제 서비스가 연결되면 동일한 질문과 정답으로 로컬·원격 품질과 지연을 비교하고 결과에 따라 활성화한다. 현재 Vercel OIDC 연결은 결제수단 미등록으로 HTTP 403을 반환했다. 이 장애를 모의 시험의 성공으로 대체하지 않는다.

## 운영 검증

배포 전 전체 테스트, 타입 검사, 린트, 빌드, 수치 검증, RAG 평가, 주요 사용자 여정을 검사한다. 고정 평가와 배포 후 공개 API·화면 검증을 반복 실행할 수 있도록 자동화하고 실패를 종료 코드와 원본 보고서에 남긴다. 검증된 소스만 push하고 도메인 연결 전 운영 설정의 배포에서 확인한 뒤 승격한다. 공유 Supabase의 무관한 테이블과 사용자 미추적 파일은 보존한다.
