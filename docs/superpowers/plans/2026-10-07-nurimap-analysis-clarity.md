# 누리맵 분석 표시 후속 개선 계획

**Goal:** 실행된 분석과 다음 분석 추천을 구분하고 작은 화면에서 결과 접근성을 검증한다.

**Architecture:** 분석 추천은 실행 없이 종류를 탐색하는 기존 동작을 유지한다. 추천 영역의 제목과 설명을 명확히 하고, 실행 조건에는 결과 context의 실제 방식을 표시한다. 모바일 가로 화면은 실제 결과의 스크롤 접근성을 확인해 재현된 문제만 수정한다.

**Tech Stack:** 기존 React, TypeScript, Vitest, Playwright. 새 의존성·유료 기능 없음.

- [x] 추천 탐색과 적용 방식 구분의 회귀 검사를 작성하고 실패를 확인한다.
- [x] 분석 추천 안내와 실제 방식 표시를 최소 수정한다.
- [x] 모바일 가로 화면의 실제 결과 접근성을 독립적으로 검증한다.
- [x] 관련 단위 검사, 타입, 빌드, 브라우저 검사를 실행한다.
- [ ] 변경을 리뷰하고 push·운영 배포 SHA 및 사용자 동작을 확인한다.

## 검증 기록

실행된 추세와 다음 분석의 추천 선택이 혼동되던 표시를 분리했다. 추천 유형 탐색만으로 실행 결과가 바뀌지 않는 기존 계약을 유지하고, 실제 적용 조건에 context의 방식을 표시한다. 단독 실행이 앞 테스트의 패널 열림 상태에 의존하던 추세 검사도 패널을 직접 열도록 수정했다.

운영 844×390px에서 결과 헤더가 탭과 목록을 시트 밖으로 밀어내는 결함을 재현했다. 높이 600px 이하의 좁은 화면에서 결과 패널 전체를 스크롤하도록 CSS를 수정했다. 사용자 휠 입력, 화면 내 좌표와 elementFromPoint, 근거 탭 전환, 순위 클릭으로 실제 도달성을 검증한다.

관련 단위 105개, 브라우저 E2E 32개, 프로덕션 빌드·타입 검사·변경 파일 lint가 통과했다. 가로 화면 밝은·어두운·고대비 3개 조합도 통과했다. 읽기 전용 독립 리뷰에서 차단 문제는 없었다. 수치 계산·RAG·LLM·DB·분석 API는 변경하지 않았다. 운영 검사의 사용 이벤트 전송은 가로채 집계를 증가시키지 않는다.
