# 지역 지도 범위와 분석 대기 시간 개선

## 목표와 검증 기준

양산시 유입인구 분석의 결과와 지도가 같은 지역을 표시해야 한다. 지도에는 요청 지역 경계만 남기고 전체 경계가 화면에 들어오도록 맞춘다. 전체 지역 분석은 원래 경계를 복원한다. 같은 지역에서 지표를 바꾸면 사용자가 조작한 카메라를 유지한다. 순위와 수치는 변경하지 않는다.

LLM은 기존의 규칙 우선 해석을 유지하고 성공한 해석만 재사용한다. 실패와 지원하지 않는 질문은 저장하지 않는다. 모델과 연결 설정이 달라지면 재사용하지 않는다. 초기 자료 조회가 느릴 때는 공개 Supabase 읽기만 4초 후 중단하고 기존 공식 자료 fallback을 사용한다. 동기화 작업의 대기 동작은 유지한다.

## 구현과 측정

지도에 전달하는 경계와 시군구 라벨용 지역 목록을 분석 범위로 제한한다. 실제 양산 자료는 행정동 13개, 시군구 1개, 격자 283개이며 경남 전체는 각각 305개, 22개, 1,750개다. 상위 순위 개수와 지도 경계 개수는 분리한다. 카메라는 경계의 실제 좌표 범위가 바뀔 때 맞추고 같은 범위에서는 수동 위치를 보존한다. Kakao와 대체 SVG 지도를 함께 검증한다.

해석 캐시는 서버 인스턴스의 메모리에 5분 동안 최대 100개를 유지한다. 동일한 진행 중 요청을 공유하고 실패는 저장하지 않는다. 질문과 설정으로 만든 해시를 키로 사용하며 별도 저장소나 원격 임베딩은 추가하지 않는다. 재사용 응답도 복사해 요청 간 변형을 방지한다. 분석 값은 캐시하지 않는다.

실제 LLM 제공사에 같은 질문 `가기 힘든 지역`을 3회 처리했다. 적용 전 3회 호출, 3,819토큰, 820/839/877ms였다. 적용 후 1회 호출, 1,273토큰, 최초 924ms와 재사용 2회 각각 반올림 0ms였다. 세 결과 모두 `rankHospitalScarcity`였다. 동시 2요청도 1회 호출, 1,273토큰으로 같은 해석을 얻었다. 명확한 규칙 질문 `진주시 고령인구 비율`은 호출과 토큰이 모두 0이었다.

측정 시간은 HTTP 왕복을 제외한 서버 함수 시간이며 표본은 LLM 질문 1개다. 최초 요청의 개선으로 해석하지 않는다. 재사용은 같은 서버 인스턴스와 5분 이내에 한정하며 서버리스의 다른 인스턴스나 콜드 시작에서는 새 호출이 발생할 수 있다. 측정 로그에는 키를 기록하지 않는다.

Supabase 공개 조회는 공식 [abortSignal 문서](https://supabase.com/docs/reference/javascript/db-abortsignal)의 방식으로 실제 요청을 취소한다. 공식 스냅샷 fallback과 정상 조회의 메타데이터를 유지한다. 앞선 데이터 로딩의 간헐적인 60초 지연 원인은 확정되지 않았지만, 이 조회가 무제한으로 화면 준비를 막는 경로는 제거했다.

재현: `npm test`, `npm run build`, `npx playwright test`, `EXPECTED_SHA`와 `UX_VERIFY_URL`을 지정한 `node scripts/verify-map-scope.mjs`. 운영 지도 검증은 익명 사용 이벤트를 가로채 통계를 늘리지 않는다.

로컬 프로덕션 HTTP 요청 3회도 같은 도구를 반환했다. 최초 1,052ms, 캐시 재사용 13ms·7ms였고 후속 2응답 diagnostics는 aiAttempted=false와 cache=hit였다. 전체 단위 검사 2,267개와 프로덕션 빌드·타입 검사, 변경 파일 lint가 통과했다. lint는 오류 0개·기존 지도 효과 의존성 경고 1개였다. 기존 카메라 검사 4개를 유지하고 범위 변경·전체 복원·동일 범위 수동 확대 보존 검사를 추가했다.

새 빌드의 데스크톱·모바일 E2E 36개가 모두 통과했다. 양산 지역 경계만 남는지, 대체 지도의 경계 크기가 확대되는지, 경남 전체 검색으로 모든 경계를 복원하는지를 포함한다.

운영 배포 e8fa3932cfb305b83de39f1fec7653107047d900과 health SHA가 일치했다. 실제 Kakao 지도에서 데스크톱·모바일 모두 전체 폴리곤 488개에서 양산 13개로 줄고, 전체 분석 시 488개로 복원했다. 지도 축척은 데스크톱 16km→4km→32km, 모바일 32km→8km→32km였고 브라우저 오류는 0개였다. 지도 보기로 시트를 닫고 타일이 실제로 로드된 화면을 확인했다. Aside MCP snapshot으로도 양산 순위 13개와 4km 축척을 확인했다. Aside 자체 스크린샷 캡처는 CDP timeout이 발생해 Playwright 운영 스크린샷으로 시각 검증했다.

운영 HTTP에서 같은 LLM 질문 3회는 1,823ms·259ms·207ms였으며 후속 두 응답은 신규 LLM 호출 없이 cache=hit였다. 이 역시 같은 인스턴스의 표본 1질문에 대한 실측이다. 해당 소스 커밋의 main·작업 브랜치 GitHub CI가 모두 성공했고, 수치·RAG 게이트와 운영 스모크까지 통과했다.
