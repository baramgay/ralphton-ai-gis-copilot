# 질문 입력 중 지도 재생성 제거

운영 시군구 유입인구 분석을 유지한 채 다음 질문의 `abc`를 입력하면 지도 폴리곤 209개가 모두 새 ID로 바뀌었다. 데이터와 범위가 바뀌지 않았는데 지도에 넘기는 배열·Map·Set 참조가 매번 새로 생성되어 Kakao 오버레이 효과가 다시 실행된다.

목표는 질문 입력 중 기존 지도와 수동 카메라를 유지하는 것이다. 분석·범위·시설·선택이 실제로 바뀌면 필요한 지도 갱신은 유지한다. 로딩 화면에서 본 화면으로 넘어갈 때 React 훅 순서도 동일해야 한다.

- [x] 변경 전 재생성 회귀 증명
- [x] 지도 입력 자료의 참조 안정화
- [ ] 관련 회귀·빌드·실제 지도 재검증
- [ ] push·운영 배포 SHA 확인

정상 첫 LLM 요청은 이미 1회 호출이며, RAG 검색 3질문의 중앙값은 0.216~0.244ms였다. 근거와 해석 예시를 줄이는 변경은 정확도 손실에 비해 체감 이득이 확인되지 않아 적용하지 않는다. timeout 후 재시도 정책 변경도 복구 기회를 줄일 수 있어 유지한다.

실제 CopilotApp과 KakaoMap에 SDK만 대체한 회귀 검사에서 두 폴리곤에 입력 3회 시 변경 전 생성자 6회 추가 호출, 변경 후 0회가 확인됐다. 카메라 추가 호출은 0회이고 지도 입력 자료의 참조도 유지된다. 기존 회귀를 포함한 관련 검사 114개와 마지막 입력 회귀 검사, 프로덕션 빌드·타입 검사·lint가 통과했다. lint는 오류와 경고 모두 0개였다. 모든 새 훅은 로딩·오류의 조기 반환보다 앞에 둔다.

새 빌드의 전체 E2E 36개가 통과했다. 운영 재검증은 1440px·390px에서 양산 범위·축척·전체 복원과 시군구 분석 후 다음 질문 입력 중 기존 폴리곤 ID 유지까지 확인한다.
