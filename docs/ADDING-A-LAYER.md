# 민간데이터 레이어 추가하기

이 도구의 주 기능은 **민간데이터를 자연어로 묻는 GIS 분석**이다. 데이터는 계속 늘어나므로,
새 레이어를 붙이는 길을 좁고 분명하게 해 둔다. 아래 순서대로 하면 라우팅·집계·내보내기가
자동으로 따라온다.

## 순서

1. **어댑터** — `scripts/adapters/<layer-id>.mjs`
   원자료 → `public/data/layers/<layer-id>.json` 큐브.
   순수 계산은 `export`해서 유닛테스트를 붙인다(스트리밍 파싱과 분리).

2. **카탈로그** — `src/lib/layers/catalog.ts`에 `LayerDescriptor` 추가 후 `CUBE_LAYERS`에 등록.
   `CUBE_LAYERS`가 앱과 테스트의 단일 출처다. 따로 목록을 만들면 반드시 어긋난다(실제로 겪음).

3. **코퍼스** — `tests/layers/private-nl-corpus.test.ts`에 실무 표현을 몇 개 넣는다.
   지표마다 최소 하나는 있어야 한다(그 규칙도 테스트로 걸려 있다).

4. `npm test` — 아래 계약이 자동으로 걸린다. 통과하면 라우팅·시군구 집계·내보내기가 동작한다.

## 자동으로 걸리는 계약 (`tests/layers/new-layer-contract.test.ts`)

| 계약 | 왜 |
|---|---|
| 지표명을 그대로 물으면 자기 지표로 온다 | 사용자는 화면에서 본 이름을 그대로 친다. 트리거에 이름이 없으면 다른 레이어의 짧은 트리거가 가져간다(`1인 카드소비` → NH `카드소비`) |
| 가중치 계열이 큐브에 있다 | 없으면 `aggregateToSgg`가 0으로 나눠 **시군구 값이 통째로 null**이 된다. 읍면동 화면은 멀쩡해서 눈치채기 어렵다(실제로 22개 지표가 그랬다) |
| 산식·한계·트리거가 비어 있지 않다 | 화면의 방법론·해석 주의사항이 여기서 나온다 |
| 계열 길이 = 관측 월 수, 기준월이 구간 안 | 길이가 어긋나면 추세·프로파일이 조용히 엉킨다 |

추가로 `sgg-aggregation-invariants.test.ts`가 실제 큐브에 **단위 기준** 성질을 건다
(명·건·백만원은 합, %·점·만원/월은 구성원 최소~최대 사이). 기대값을 카탈로그의
`aggregation`에서 읽으면 자기참조가 되어 결함을 놓친다 — 단위로 판단하는 이유다.

## 지표를 정의할 때 주의

- **`aggregation`**: 더할 수 있는 양이면 `sum`, 비율·평균이면 `weightedAvg` + `weightKey`.
  가중치로 쓸 계열은 **같은 큐브 안에** 있어야 한다(어댑터가 함께 내보낼 것).
- **`scope: "sgg"`**: 원자료가 시군구까지만 있는 지표(KCB 전출)에 붙인다. 읍면동 셀에는 같은
  값이 복제돼 있어, 이것 없이는 같은 값 30개에 임의 순위가 붙는다.
- **`triggers`**: 지표명 자체를 반드시 포함. 긴 문구를 넣으면 `pruneOverlaps`가 짧은 매칭을
  걷어내므로, 교차분석으로 새는 표현도 트리거 하나로 잡을 수 있다.
- **`label`**: 다른 레이어와 겹치지 않게. 겹치면 이름이 정확히 맞는 쪽으로 보내고 넓은 쪽은
  이름을 바꾼다(`고령비중` → `생활인구 고령비중`).
