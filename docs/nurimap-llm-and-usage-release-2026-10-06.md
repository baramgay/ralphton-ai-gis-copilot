# LLM 해석 및 익명 사용 통계 검증

## 변경 범위

원격 임베딩이나 새 모델을 추가하지 않고 기존 LLM의 지역 조건, 후보 지표, 응답 형식과 완료 상태를 검증하도록 보강했다. 규칙으로 답할 수 있는 질문은 LLM을 호출하지 않는다. 재시도는 같은 모델에서 한 번으로 제한하고 전체 호출 예산은 15초로 설정했다. 숫자는 기존 결정적 분석 코드로 계산한다.

동명이동은 시군구 확인 후 선택하며, 지역이 모호하면 실행 가능한 확인 질문을 표시한다. 창원시 질문의 범위를 의창구로 임의 축소하지 않는다. 두 개 이상의 명시된 지역을 비교하며, 같은 지역 반복이나 지역 없는 비교에 다른 지역을 만들어 넣지 않는다.

익명 사용 통계는 성공 분석, 실제 사용 데이터, 방문, 내보내기, 공유를 집계한다. 관리자 화면은 `/admin/usage`이고 일·주·월, 기간 선택, 그래프, 데이터별 표, CSV를 제공한다. 집계 정의와 운영 방법은 `nurimap-usage-analytics.md`를 참조한다.

## 검증 기록

- 최종 전체 단위 테스트: 163개 파일, 2,229개 통과. 타입 검사와 운영 빌드 통과. 전체 lint 오류 0개, 기존 경고 47개. 새 사용 통계 관련 scoped lint 오류 0개.
- Playwright E2E: 28개 통과.
- 변경 전 실제 운영 HTTP 22문항: 17개 통과, 5개 실패. LLM 경로 5개는 실제 모델 응답을 사용했다. LLM 경로 HTTP 중앙값 1,694ms, p95 4,496ms. 이 작은 표본에서 일반적인 성능 향상을 추정하지 않는다.
- 최초 후보 배포(dcc05c4)에서는 지역 문제를 해결했으나 상권 표현 두 건을 unsupported로 거절해 20/22였다. 검색 후보에는 올바른 카드매출액 지표가 있었고, 축소 프롬프트에서 기존 표현 연결이 빠진 것이 원인이었다. 수용 기준은 변경하지 않았다.
- 실제 Supabase 롤백 트랜잭션에서 중복 이벤트·중복 데이터 제거, 브라우저별 일일 중복 제거, 방문 2/분석 2/내보내기 1/공유 1 및 데이터별 합계, 오래된 receipt 정리를 검사했다. 빈 분석은 SQL 오류 22023으로 거부됐다. 테스트는 ROLLBACK하여 합계 0행을 확인했다. 재현 SQL은 `verification/nurimap-usage-db-rollback.sql`이다.
- 두 전용 테이블의 RLS가 활성화되고 anon/authenticated의 조회와 쓰기가 차단됐다. 집계 함수는 SECURITY INVOKER이며 anon/authenticated 실행은 차단되고 service_role만 실행할 수 있었다.
- 최초 후보 배포에서 인증 없는 조회 401, 관리자 로그인 200, 인증된 일·주·월 조회 200 및 기간별 합계 일치를 확인했다.

Vercel의 실제 팀 설정은 hobby/active로 확인했다. 유료 플랜, 카드 등록, 원격 임베딩을 추가하지 않았다. 기존 LLM API 비용은 제공사 정책을 따른다. API 비밀값과 관리자 비밀번호는 검증 보고서나 저장소에 기록하지 않았다.

로컬에는 실제 서비스 키가 없어 실제 LLM·DB 검증 근거로 사용하지 않았다. 보호된 Vercel 후보 배포를 통해 운영 환경을 검증했다. 보호된 배포의 CLI 중계 시간은 실제 운영 HTTP 시간과 비교하지 않는다.

## 최종 운영 검증

공공 의료 지표를 민간 후보로 제시하던 경로 불일치를 제거하고, 공공 도구에도 검색된 문서의 구어체 표현을 전달했다. 검색된 의료 취약 도구가 있을 때만 접근성 예시를 제공한다. 새로운 지표나 지역을 만드는 것은 계속 거부한다.

보호된 후보 배포 8814bd1의 고정 HTTP 평가 22/22가 통과했다. main push 및 후보의 운영 승격 후 gnbc.site에서 같은 22/22가 다시 통과했고 실제 LLM 경로 5/5를 확인했다. 운영 HTTP LLM 경로 중앙값은 879ms, p95는 1,498ms였다. 변경 전 1,694ms/4,496ms와 비교할 수 있지만 표본 5건이므로 일반적인 개선율이나 장기 SLA로 해석하지 않는다. 규칙 경로 17건의 중앙값은 156ms, p95는 327ms였다.

운영 RAG 검색 42문항과 parser 8문항은 실패 0건이었다. 원격 임베딩은 사용하지 않았다. 수치 검증은 336,002개 검사, 자료 21개, 시군구 밀도 집계 22개에서 실패 0건이었다. 의료기관 전체 4,254개, 가호동 30개와 독립 지도 경계 계산 30개 일치, 진주시 486개, 의원 필터 14개에서도 지역 전체 30개를 유지했다. 시설 회귀의 Node HTTPS 연결은 약한 인증서 키 오류가 있었으나 인증서 검증을 유지한 Chromium HTTPS로 같은 검사를 통과했다. 원본 스크립트와 TLS 설정은 변경하지 않았다.

관리자 화면 검증 중 고정 앱 viewport 때문에 하단이 잘리는 문제와 고대비 선택·hover 버튼의 가독성 문제를 발견했다. 전용 내부 스크롤과 페이지에만 적용되는 테마 규칙으로 수정했다. 4ee2d66 운영 배포에서 390px/1440px, 밝은·어두운·고대비 테마의 로그인, 일·주·월 조회, 실제 하단 이동, 가로 넘침 없음, CSV 내용, 로그아웃 후 401, 브라우저 오류 0개를 확인했다. 하단과 고대비 화면을 직접 확인했다. 재현 명령은 `node scripts/verify-nurimap-usage-dashboard.mjs https://gnbc.site`이다.

실제 Chromium 방문 이벤트와 성공한 주민등록 인구 분석 이벤트가 각각 HTTP 200으로 수집됐다. 본문은 visitorId/events와 id/kind/datasets만 포함했다. 검증 로그에는 종류·데이터 ID·HTTP 상태만 남겼다. 이번 배포부터 수집하며 운영 검증의 실제 방문·분석도 포함된다. 과거 방문 기록을 만들어 넣지 않았다.

앱 코드는 4ee2d66에서 운영 확인했고 이후 검증 스크립트·문서 정리는 앱 코드를 변경하지 않는다. 최종 CI와 운영 health의 commitSha는 별도로 확인한다. 비밀번호는 gitignored `.vercel/nurimap-usage-admin.txt`에만 보관하고 Production 민감 환경 변수로 설정했다.
