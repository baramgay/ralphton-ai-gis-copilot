## 4. 지금의 디자인 토큰 (여기에 얹어 주십시오)

`src/app/globals.css` 최상단에 CSS 변수로 있습니다. **토큰 이름을 바꾸지 말고 값을 바꾸거나,
새 토큰을 추가하는 쪽**으로 주십시오.

```css
:root {
  --background: #f4f7fb;  --foreground: #0f172a;
  --panel-left: 300px;    --panel-right: 360px;
  --ui-space: 0.75rem;    --ui-radius: 0.9rem;   --ui-chip: 0.625rem;
  /* 글자 크기는 이미 한 벌로 묶여 있습니다 */
  --fs-caption: 0.6875rem; --fs-chip: 0.75rem; --fs-body: 0.8125rem;
  --fs-body-lg: 0.875rem;  --fs-title: 0.9375rem; --fs-display: 1.0625rem;
  --lh-tight: 1.35; --lh-body: 1.55;
  /* 면·선·글자·강조 */
  --surface-0 … --surface-3, --surface-map
  --border-1, --border-2, --border-soft
  --text-1 … --text-4
  --accent: #2563eb; --accent-soft; --accent-line; --accent-warm; --accent-warm-soft;
  --shadow-panel; --input-bg;
}
```

**테마는 넷입니다**: 시스템 / 라이트 / 다크 / **고대비**. `html[data-theme="dark"]`,
`html[data-theme="contrast"]`로 갈리고 라이트는 속성이 없습니다. 현재 기본은 **다크(데이터룸)**
입니다. 넷 모두 시안이 필요합니다 — 특히 고대비는 유리 재질과 정면으로 부딪히는 자리라 **거기서
유리를 어떻게 포기할지**를 보여 주셔야 합니다.

## 5. 원하는 것 — Apple 스타일과 Liquid Glass를 **어디에** 쓰는가

「전부 유리로」가 아닙니다. 재질을 **역할로** 갈라 주십시오.

| 자리 | 재질 | 이유 |
|---|---|---|
| 지도 위 부유 컨트롤(`map-float-bar`, `map-float-dock`, `probe-card`) | **Liquid Glass** | 지도가 비쳐야 위치 감각이 유지됩니다 |
| 좌·우 패널, 결과 표, 보고서 | **불투명 면** | 숫자를 읽는 자리입니다. 뒤가 비치면 읽기가 나빠집니다 |
| 상단바 | 얇은 유리(스크롤 시 굳어짐) | 지도와 패널을 잇는 층 |
| 모바일 시트 | 유리 + 손잡이 | 지도 위로 올라오는 층이라 |

Liquid Glass에서 우리가 기대하는 것:

1. **깊이** — 배경 흐림 + 아주 옅은 채도 상승, 그 위 1px 안쪽 하이라이트(specular edge).
2. **가장자리** — 위쪽은 밝고 아래쪽은 어두운 테두리. 빛이 위에서 온다는 일관된 규칙.
3. **움직임** — 눌림·시트 전환에 스프링 감(과하지 않게, 200~320ms).
4. **적응** — 유리 뒤 지도가 밝은 곳/어두운 곳일 때 글자가 다 읽혀야 합니다. **이것이 이 의뢰의
   가장 어려운 부분입니다.** 지도는 사용자가 움직이므로 배경을 우리가 정할 수 없습니다.

Apple HIG에서 가져오고 싶은 것: 44pt 터치 타깃, 넉넉한 여백 대신 **일관된 여백 계단**,
굵기로만 위계를 만드는 타이포(색을 덜 쓰기), 상태 변화의 부드러운 전이, 그림자 남발 금지.

**한글 타이포**: Pretendard를 씁니다(자체 호스팅, 외부 로드 금지). SF Pro의 자간·굵기 감각을
Pretendard로 어떻게 옮길지 값으로 적어 주십시오(letter-spacing·font-weight 매핑).

## 6. 넘지 말아야 할 선 (지키지 않으면 이식이 불가능합니다)

- **외부 CDN·외부 폰트 로드 금지.** 폰트는 자체 호스팅 Pretendard, 아이콘은 인라인 SVG 또는 문자.
- **프레임워크 교체 금지.** Next.js 16 App Router + React 19 + Tailwind v4입니다. 시안은 순수
  HTML/CSS로 주시되, 클래스 이름은 §3 목록을 따라 주십시오.
- **클래스 이름 바꾸지 마십시오.** e2e와 컴포넌트 검사가 이 이름으로 화면을 찾습니다.
- **문구를 지어내지 마십시오.** 실제 문구를 쓰십시오(용어집·아래 부록 B).
- **지도를 가리지 마십시오.** 이미 한 번 데었습니다 — 지점 분석 카드가 393×727 화면에서 세로
  314px을 차지해 지도에 남는 자리가 173px(24%)뿐이었고, **두 번째 지점을 찍을 수 없었습니다.**
- **Tailwind v4 함정**: `-translate-x-1/2`는 `transform`이 아니라 `translate` 속성을 씁니다.
  `transform: none`으로 덮으려다 도크가 화면 밖(x=-196.5)으로 나간 적이 있습니다.

## 7. 성능 예산 — 유리는 공짜가 아닙니다

현재 실측치입니다. **이보다 나빠지면 안 됩니다.**

| 지표 | 현재 |
|---|---|
| FCP | 195ms |
| h1 표시 | 205ms |
| 모바일 초기 로딩 | 1.2초대 |

`backdrop-filter`는 합성 비용이 크고, **지도가 움직이는 동안** 유리 뒤가 매 프레임 다시 흐려집니다.
그래서 요청드립니다:

- 유리를 쓴 화면에서 **지도 팬·줌 중 FPS를 실측**해 주십시오(Pixel 5급 기기 배율, 크로미움 가능).
- 60fps를 못 지키는 자리가 있으면 **어떻게 물러설지**를 시안에 함께 넣어 주십시오
  (`@media (prefers-reduced-transparency)`, 저사양 감지, 지도 이동 중 흐림 일시 해제 등).
- 「느낌상 부드럽다」는 답은 받지 않습니다. **수치와 측정 방법**을 적어 주십시오.

## 8. 접근성 — 여기서 이미 여러 번 데었습니다

- **대비비**: 유리 위 글자가 지도의 밝은 곳/어두운 곳 **양쪽에서** WCAG AA(본문 4.5:1, 큰 글자
  3:1)를 넘어야 합니다. 실제 지도 타일 위에서 재 주십시오 — 단색 배경 위 계산은 답이 아닙니다.
- **고대비 테마에서는 유리를 포기해도 됩니다.** 다만 그때 화면이 무너지지 않아야 합니다.
- **`toBeVisible`은 가림을 못 잡습니다.** 판정은 `document.elementFromPoint(x, y)`로 하십시오 —
  「보인다」가 아니라 「그 자리를 누르면 그것이 받는가」입니다. 마우스 클릭은 통과하고 탭은 실패한
  경우가 실제로 있었습니다.
- 44pt(약 44px) 터치 타깃. 지금 `map-float-bar` 버튼이 그보다 작습니다.

1. **주기능이 모바일에서 도달 불가** — 질의창이 패널 안에 있어 패널을 열어야 닿았습니다.
2. **떠 있는 버튼 줄이 두 줄로 접혀** 안내 카드 밑으로 들어가 눌리지 않았습니다.
3. **지점 카드가 지도의 76%를 덮어** 두 번째 지점을 찍을 수 없었습니다(접기로 해결).
4. **안내 카드가 지도 한가운데를 덮어** 첫 탭을 삼켰습니다.
5. **`translate` vs `transform`** — Tailwind v4에서 도크가 화면 밖으로 나갔습니다.
6. **다크 블록에만 정의한 토큰**은 라이트에서 조용히 무시됩니다(값이 사라져 화면이 무너집니다).
7. **클라이언트로 옮긴 렌더**가 첫 페인트를 3.2초 늦춘 적이 있습니다.
