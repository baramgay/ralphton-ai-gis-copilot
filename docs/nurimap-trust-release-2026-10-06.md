# 누리맵 사용자 경험·공식 통계·검색 개선 검증

## 변경

질문을 중심으로 지도와 결과 작업 공간을 재구성했다. 결과는 순위, 선택 지역, 분석 근거 탭으로 나누고 모바일에서는 지도와 결과를 전환한다. 공유와 내보내기는 결과에서 바로 실행한다. 기준월, 자료 정의와 근거는 화면과 CSV·Markdown·PDF용 HTML·HWP용 HTML·슬라이드에 함께 표시한다.

행정안전부 공개 주민등록 CSV 65개에서 2025-09부터 2026-09까지 13개월의 경남 305개 읍면동 통계를 연결했다. 경계에 없는 5개 출장소는 공식 소속 읍면동에 합산했다. 1인세대는 세대원수별 자료를 사용하며, 출생·사망은 출생등록·사망말소 기준이다. 더 최신이며 완전한 공식 캐시는 유지한다. 시설은 기존 실제 HIRA 자료를 사용한다. 이 인구 자료는 월별 묶음 자료이며 매 방문 시 원기관에서 새로 가져오는 방식은 아니다.

검색에서는 대조 설명의 다른 데이터 이름을 긍정 근거로 취급하던 문제, 의역의 주제 누락, 지원하지 않는 혼합 질문을 수정했다. 임베딩은 10개 단위 요청, 순서 복원, 벡터 검증, 제공자·모델·코퍼스별 캐시 분리와 차원 불일치 차단을 적용했다.

## 로컬 검증

- Vitest: 155개 파일, 2,129개 테스트 통과. 최종 UI는 기존 91개와 의료기관 집계 회귀 3개를 포함한 94개가 통과했다. Ubuntu CI는 2,121개 통과·플랫폼별 8개 건너뜀으로 구분한다.
- TypeScript와 production build 통과. ESLint 오류 0개, 기존 경고 47개.
- Playwright: 데스크톱·모바일 28개 시나리오 통과.
- 화면: 390, 768, 1280, 1440px에서 분석·순위·비교·공유·CSV·인쇄용 보고서·키보드 이동을 확인했다.
- 공식 CSV 독립 검증: Python 표준 CSV와 정수 합산으로 732,347개 검사를 통과했다. 원자료 SHA256, 101개 연령, 읍면동·시군구·경남 합계와 모든 출력 지표를 비교했다.
- 공식 snapshot 분석 수치: 336,002개 검사, 21개 분석 큐브와 22개 시군구 밀도 집계를 통과했다.
- 고정 한국어 검색 평가: 관련 질문 top1·top5 각각 14/14, 무근거·지원 범위 밖 질문 빈 결과 10/10. 별도 의역·대조·복합·부정 평가 9/9.

평가 범위의 통과는 임의의 모든 질문에 대한 정답 보장을 뜻하지 않는다. 원자료와 계산 검증은 주민등록 통계에 적용되며 다른 공급자의 지표를 공식 인구 통계로 바꾸지 않는다.

## 남은 사용자 설정

실제 원격 임베딩은 Vercel AI Gateway가 `403 customer_verification_required`를 반환하여 완료하지 못했다. 로컬 fallback 결과를 원격 성공으로 계산하지 않았다. 별도 서비스 키 또는 Gateway 계정 설정 후 같은 질문의 로컬·원격 품질, 지연, 실제 원격 적용을 재검증해야 한다.

설정 순서와 그록봇에 전달할 문구는 [그록봇 지시서](nurimap-grokbot-instructions.md)에 있다. 공식 인구 자료의 다음 기준월 갱신 절차는 [공식 자료 운영 안내](nurimap-official-data-access.md)에 있다.

## 출시 기록

- 운영: https://gnbc.site . 기능 소스는 `04e65af1f313a22999831ff340220844988d9285`, 배포는 `dpl_3ExqP9HiurQE4jTWhiGdbTt42mg6`이다. main에 push했고 도메인 연결 전 health·기준월·소스 SHA를 검사한 뒤 승격했다. 이후 main의 문서·운영 검사·workflow 커밋은 앱 소스 변경 없이 갱신하며, 배포된 기능 소스 SHA와 구분한다.
- 운영 검색 42개와 파서 8개 모두 통과했다. 화면 390×844, 768×1024, 1280×800, 1440×900에서 질문·결과·CSV·보고서·공유·비교·키보드 흐름을 통과했다.
- 운영 분석 수치 336,002건을 다시 통과했다. 배포된 공식 snapshot과 manifest의 SHA256은 검증한 파일과 같았다. 인구 합계 3,190,549명, 세대 1,559,208, 1인세대 665,508, 65세 이상 778,644명, 출생등록 1,368, 사망말소 2,111, 자연증감 −743으로 원자료와 일치했다. 운영 CSV의 기준월·원기관 URL·자료 정의도 확인했다. 총인구 1위는 양산시 물금읍 117,251명이었다.
- 실제 Kakao 지도에서 중앙동을 진주시 `4817056500`와 창원시성산구 `4812352000`로 구분하여 선택·공유 코드가 맞는지 확인했다. 지점 35.19587, 128.09057에서 반경 1/2/3km 시설 수 88/160/289를 독립 Haversine 계산과 비교해 일치했다.
- 지도 지점 카드와 패널 버튼의 1,536px² 겹침을 재현하고 데스크톱 카드 간격을 수정했다. 수정 후 production build와 E2E 28개를 다시 통과했으며 운영 겹침 면적은 0이었다.
- 진주시 최근 3개월 카드매출 추세의 화면 24행·CSV 30행·보고서 20행이 모두 진주시 범위였고 공유 재로드에서도 유지됐다. 표시 행 수 차이는 화면·출력별 기존 행 제한에 따른다.
- 고정 검색의 로컬 CPU 측정은 warmup 20회 후 200회에서 p50 0.2015ms, p95 0.3326ms였다. HTTP·모델 생성·화면 렌더링과 실제 원격 임베딩 지연을 포함하지 않는다.
- 기본 브랜치에 6시간 간격 운영 회귀 workflow를 포함했다. 수동 실행 [Production quality](https://github.com/baramgay/ralphton-ai-gis-copilot/actions/runs/37415196552)가 통과했다. 최종 기능 소스 [CI](https://github.com/baramgay/ralphton-ai-gis-copilot/actions/runs/37395546493)는 단위·빌드·수치·검색·브라우저 검사까지 모두 통과했다.
- 기존 운영 smoke는 개편 전 UI 선택자를 사용해 세 검사가 실패했다. 새 작업 버튼·더 보기·결과 탭과 완료 대기로 검사 흐름을 갱신한 뒤 용어 12개·지점 20개·시군구 8개·지도 겹침 115개 조건이 운영에서 통과했다. 검사 삭제나 실패 무시는 적용하지 않았다. 최종 시군구 검사에서 넓은 탐색 간격이 육지를 놓치는 실패가 재현되어 좌표 간격을 0.1에서 0.05로 줄였다. 기존 호버·클릭·선택 일치 조건 그대로 운영 재검사가 통과했다. 기능 커밋의 main CI smoke는 이 검사 실패를 기록했으며 코드 검증 job과 구분한다.
- 실제 원격 임베딩 운영 비교는 `actualRemote: false`, `remote_not_applied`, 종료 코드 2였다. 계정 설정과 실제 품질·지연·비용 확인은 위 사용자 설정 항목대로 남아 있다.

## 최종 발견 오류와 운영 재검증

인구 분석에서는 의료기관 핀이 숨겨지므로 지도 후보를 세면 선택 지역 통계가 0이 되는 오류를 발견했다. 전체 시설 snapshot에서 해당 읍면동·시군구 코드를 집계하도록 수정했다. 가호동 `4817074000`의 원자료 코드 배정 30개와 독립 폴리곤 포함 판정의 시설 ID 집합이 일치했다. 실제 운영 인구 화면은 가호동 30개, 진주시 486개로 표시됐다. 의원 검색 14개로 제한해도 가호동 전체 통계 30개는 유지됐다. 단위 테스트는 유형 필터 901개·지도 핀 상한 900개·전체 통계 902개가 서로 섞이지 않는지도 확인했다. 이 운영 검사를 `node scripts/verify-region-facilities-prod.mjs https://gnbc.site`로 보존하고 6시간 회귀 workflow에 포함했다. 이후 시설 갱신은 숫자를 고정하지 않고 같은 시점의 snapshot과 화면을 비교한다.

고대비 순위 번호의 흰 바탕·흰 글자, 연결 상태의 옅은 글자, 차트 날짜와 양수 자연증감의 대비를 수정했다. 최종 운영 검사에서는 390·1440px와 라이트·다크·고대비의 설정·결과·공식 인구 화면에서 측정 가능한 글자 2,299개가 통과했다. 가호동 +31과 양 끝 기준월은 실제 스크롤해 표시한 뒤 측정했다. 이미지 배경으로 수치 측정할 수 없는 항목은 별도로 보고하며 통과 수에 포함하지 않았다. 작은 글자 4.5:1·큰 글자 3:1과 정확한 18pt/14pt 굵은 글자 기준을 적용하고 반올림으로 미달을 통과시키지 않았다. 기준은 [WCAG 2.2 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)이다. 이 결과는 전체 WCAG 인증을 뜻하지 않는다.

운영 검사 16종 중 최초 묶음 실행은 시군구 좌표 탐색과 성능에서 실패했다. 시군구는 위 수정 후 같은 조건으로 통과했다. 성능은 전체 단위 테스트와 동시에 측정해 FCP 중앙값 896ms로 예산을 초과했다. 다른 검사가 끝난 뒤 동일한 예산과 새 브라우저 문맥 5회로 재측정하여 FCP 352ms(예산 400ms), 제목 364ms(예산 450ms)로 통과했다. 질문 작업 영역 준비는 중앙값 4,172ms로 별도 기록했으며 첫 글자 표시 시각과 구분한다. Windows 개발 호스트와 해당 네트워크에서 측정한 관측값이며 전체 사용자의 지연 보장은 아니다. 나머지 14종은 최초 실행에서 통과했다. 최종 각 검사의 실패를 수정·구분한 결과 16종 모두 통과했으며 원래 실패 로그는 보존했다.

최종 기능 배포에서 공식 파일 SHA256, 기준월, 305개 읍면동과 시설 4,254개를 다시 대조했다. 검색 42개·파서 8개, 336,002개 수치 검사, 네 화면 크기의 공유·내보내기·키보드 이동을 다시 통과했다. 실제 Kakao의 동명이동 선택, 반경 88/160/289개, 지점 카드 겹침 0, 진주시 추세·CSV·보고서 범위 역시 최종 기능 소스에서 재검증했다.
